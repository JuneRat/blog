# 首次安装

在仓库根目录构建后台并执行 `cargo run -p server -- serve`。未设置 `DATABASE_URL`、也没有 `BLOG_CONFIG_FILE`（默认 `data/config.json`）时，服务进入安装模式，访问首页或后台跳转到 `/install`。安装页内嵌在程序中，不依赖主题、数据库或后台构建产物；完成安装前仍会检查后台产物与主题，保证可进入登录页。

1. 准备已创建的 PostgreSQL 空数据库；连接账号需具备 public schema 的建表及读写权限。向导不创建数据库、不删除表、不转换旧数据。
2. 复制启动终端显示的 256 位随机安装码。安装码只在当前进程有效，不由 HTTP 返回，重启后更换；不要公开转发启动日志。
3. 填写数据库连接地址、站点对外地址、用户名和密码。站点地址不能包含路径前缀；本地可用当前访问地址，公开部署使用 HTTPS 域名。密码沿用账号的 12–128 字符策略。
4. 提交后初始化迁移、权限目录和内置角色，创建具有本地密码的首个 Owner；完成后原进程直接切换到博客并跳转 `/admin/`，使用刚设置的账号登录。

`BLOG_PUBLIC_BASE_URL` 已设置时，表单显示该地址且不能编辑。显式提供 `DATABASE_URL` 时视为已有部署，按原方式启动；空库的受控 CLI 初始化仍可使用 `migrate` → `user create` → `user passwd` → `role assign`。这条 CLI 路径保留分步语义，不等于安装向导的原子创建。

## 配置与中断恢复

连接配置保存在 `BLOG_CONFIG_FILE`，包含 `database_url`、`public_base_url` 和随机 `installation_id`。文件含数据库凭据，Unix 权限为 600；新建父目录为 700。不保存管理员明文密码、密码哈希或安装码，不覆盖已有文件或符号链接。文件使用同目录临时文件、同步落盘、硬链接原子发布；配置目录需支持硬链接。默认配置路径及临时文件已加入 Git 忽略规则，使用自定义路径时自行保护。

配置先于数据库初始化保存。权限目录、内置角色、用户、Argon2id 密码哈希、Owner 关联、`settings.installation` 完成标记和 `installation.complete` 审计在同一数据库事务里提交。事务失败会全部回滚；数据库迁移可以保留空表，重试继续使用该文件指定的数据库与站点地址，不能从网页更换目标。并发安装受进程门闩、配置文件不覆盖规则和数据库身份锁保护，只能成功创建一套首个 Owner。

如果进程中途退出，重新启动并输入新的安装码即可继续。只有带本次配置且尚无业务数据的空基线可续装；出现已有用户（含禁用、软删除）、内容、未知表或恢复隔离标记会拒绝。若数据库已提交完成标记，重启直接进入博客；不会因 Owner 被禁用、删除或缺失而重新开放安装。事务提交结果不确定时，重试也先核对完成标记，避免重复建号。

已完成时，`/install` 跳到登录页，`/api/install` 返回 404。安装期间 `/healthz` 返回 503；完成后才按数据库健康状况返回就绪结果。反向代理或容器的启动探针应允许人工安装期间处于未就绪状态，避免循环重启。安装期间不运行预约发布任务。

配置损坏、权限过宽、已配置数据库不可连接不会重新开启无配置安装。检查报错并修复部署配置；切换为已有库或恢复库时显式设置 `DATABASE_URL`。恢复隔离规则仍生效。不要为了“重装”删除安装标记或清理业务表；需要新站点时使用独立空库和新的配置路径。

## 部署与备份

容器部署持久挂载配置目录和媒体目录，重启时使用相同工作目录或绝对 `BLOG_CONFIG_FILE`。安装后可用 `scripts/database-roles.sql` 分离结构管理与运行账号，再通过环境变量覆盖运行 DSN；密码不会通过安装状态接口回显。

安装 API 要求终端安装码、自定义请求头和同源请求；不提供公开注册、安装状态中的秘密或远程清库接口。页面禁止缓存、跨站嵌入和外部脚本。未完成安装时只暴露安装页及其静态资源。

安装文件属于部署秘密，需通过部署秘密存储单独备份；现有数据库/媒体备份工具不会自动复制它。数据库备份包含完成标记，恢复后可继续使用原配置文件并覆盖数据库地址，也可完全由环境变量配置；不要对已恢复数据库执行安装。
