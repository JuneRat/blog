# 首次安装

在仓库根目录构建后台并执行 `cargo run`。TOML（默认 `config.toml`）和环境中均未配置数据库地址，且不存在安装记录时，服务进入安装模式，访问首页或后台跳转到 `/install`。安装页内嵌在程序中，不依赖主题、数据库或后台构建产物；完成安装前仍会检查后台产物与主题，保证可进入登录页。

1. 准备已创建的 PostgreSQL 空数据库；连接账号需具备 public schema 的建表及读写权限。向导不创建数据库、不删除表、不转换旧数据。
2. 复制启动终端显示的 256 位随机安装码。安装码只在当前进程有效，不由 HTTP 返回，重启后更换；不要公开转发启动日志。
3. 填写数据库连接地址、站点对外地址、用户名和密码。站点地址不能包含路径前缀；本地可用当前访问地址，公开部署使用 HTTPS 域名。密码沿用账号的 12–128 字符策略。
4. 提交后初始化迁移、权限目录和内置角色，创建具有本地密码的首个 Owner；完成后原进程直接切换到博客并跳转 `/admin/`，使用刚设置的账号登录。

`server.public_base_url` 或 `BLOG_PUBLIC_BASE_URL` 已设置时，表单显示该地址且不能编辑。显式提供 `database.url` 或 `DATABASE_URL` 且没有安装记录时视为已有部署；有安装记录时先核对数据库完成标记；空库的受控 CLI 初始化仍可使用 `migrate` → `user create` → `user passwd` → `role assign`。这条 CLI 路径保留分步语义，不等于安装向导的原子创建。

## 配置与中断恢复

部署参数保存在 `--config` / `BLOG_CONFIG_FILE` 选定的 TOML，默认 `config.toml`。安装期间，随机安装 ID 和配置发布快照保存在旁边的临时恢复日志 `config.install-state.json`（自定义路径同样替换扩展名）。两者可能含数据库凭据，Unix 权限为 600，新建父目录为 700。不保存管理员明文密码、密码哈希或安装码，不允许符号链接。

安装记录先通过私有临时文件、fsync、硬链接发布，绝不覆盖另一安装记录，再发布 TOML。首次创建 TOML 不覆盖已有路径；预先存在且尚未配置数据库的 TOML 使用读取快照检查后原子更新，保留注释和其他配置。安装期间应避免外部同时编辑配置；检测到变化会停止写入。若在两次发布之间崩溃，安装记录可恢复尚未发布的 TOML。目录需支持硬链接。

配置先于数据库初始化保存。权限目录、内置角色、用户、Argon2id 密码哈希、Owner 关联、`[bootstrap]` 提供的初始站点值、`settings.installation` 完成标记和安装审计在同一事务里提交。失败全部回滚；数据库迁移可保留空表。重试使用安装记录绑定的数据库目标，不能从网页更换。进程门闩、安装记录不覆盖规则和数据库身份锁共同防止竞争安装。

如果进程中途退出，重新启动并输入新的安装码即可继续。只有带本次配置且尚无业务数据的空基线可续装；出现已有用户（含禁用、软删除）、内容、未知表或恢复隔离标记会拒绝。若数据库已提交完成标记，重启核对安装 ID 后清理日志并直接进入博客。事务提交结果不确定时，重试也先核对完成标记，避免重复建号。

数据库事务提交成功后，程序删除本次安装的临时日志并同步配置目录。日志已经不存在时无需处理；文件被修改、部署配置损坏或删除失败时只记录警告，不把已提交的安装报告为失败，下次启动会重试残留日志。连接失败、安装 ID 不匹配或安装未完成时不删除日志。常态运行只需要 TOML，完成标记随数据库保留；没有安装日志且已配置连接时按正常部署启动，不再要求本地安装 ID 与数据库永久绑定，也不会因 Owner 被禁用、删除或缺失而重新开放安装。

安装页先验证终端中的安装码，再显示数据库配置状态和预设站点地址；读取与提交 `/api/install` 都要求 `X-Install-Token`。

已完成时，`/install` 跳到登录页，`/api/install` 返回 404。安装期间 `/readyz` 与兼容入口 `/healthz` 返回 503；完成后才按数据库健康状况返回就绪结果。独立 `/livez` 在安装期间仍返回 200。反向代理或容器的启动探针应允许人工安装期间处于未就绪状态，避免循环重启。安装期间不运行预约发布任务，详细日志及指标语义见[可观测性](observability.md)。

配置损坏、权限过宽、已配置数据库不可连接不会重新开启无配置安装。检查报错并修复部署配置；切换为已有库或恢复库时显式设置 `DATABASE_URL`。恢复隔离规则仍生效。不要为了“重装”删除安装标记或清理业务表；需要新站点时使用独立空库和新的配置路径。

## 部署与备份

仓库提供 [Docker Compose 部署](docker-compose.md)：镜像包含后台、主题和迁移，配置与媒体使用独立持久卷，资源路径均为容器内绝对路径。自定义容器部署同样需要持久挂载配置目录和媒体目录。安装后可用 `scripts/database-roles.sql` 分离结构管理与运行账号，再通过环境变量覆盖运行 DSN；密码不会通过安装状态接口回显。

安装 API 要求终端安装码、自定义请求头和同源请求；不提供公开注册、安装状态中的秘密或远程清库接口。页面禁止缓存、跨站嵌入和外部脚本。未完成安装时只暴露安装页及其静态资源。

TOML 属于部署秘密，需通过部署秘密存储单独备份；现有数据库/媒体备份工具不会自动复制它。未完成安装的临时日志也含部署秘密，应与配置一起保护；完成后的备份和恢复不需要该文件。数据库备份包含完成标记，恢复后可继续使用原配置文件并覆盖数据库地址，也可完全由环境变量配置；不要对已恢复数据库执行安装。

运行期站点设置保存在数据库，TOML `[bootstrap]` 只提供首次安装初始值，不会在重启时覆盖后台修改；详见[配置参考](configuration.md)。
