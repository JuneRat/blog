# 领域类型与实际写入约束

本文记录当前代码的写入边界。[目标数据库设计](database-design.md)已部分接入：身份/认证版本与媒体已切换，系列关系、评论层级及去重规则仍待调整；以下实现说明不替代新方案。

## 正文与渲染预算

Post/Page 共用 `domain::content::budget`：

| 对象 | UTF-8 字节上限 | 校验位置 |
| --- | ---: | --- |
| Markdown 源文 | 1 MiB | 创建、编辑、发布，以及仓储写入前 |
| 清洗后的正文 HTML | 768 KiB | 渲染运行时及仓储写入前 |
| 完整主题页面 | 1 MiB | 主题渲染器 |

正文 HTML 与源文没有固定大小比例：实体转义、列表、表格等都可能放大输出。
因此源文达标仍须实际渲染并校验 HTML；创建草稿、保存、发布的生产仓储均在
事务开始前完成检查，超限返回 `UseCaseError::Invalid`，不改变正文、版本或引用。
主题可使用余下的 256 KiB 输出页面框架和元数据；注册主题时另用达到正文
HTML 上限的 Post/Page 校验模板，拒绝重复输出正文等明显超预算的主题。
任意自定义模板仍须遵守页面预算，运行时保留最终上限检查。

结构有效的历史大正文仍可重建、读取、缩短或移入回收站；新容量策略不阻止
用户打开旧内容修复。新建、编辑和再次发布必须符合当前预算。本次不自动
截断历史内容，也不改变 Markdown 渲染版本；已有超限公开内容需主动缩减。

## 类型与重建

- `Username` 统一 trim 和 ASCII 小写；`Email` 统一 trim，并拒绝多重 `@`、
  空域名段、空白和控制字符。邮箱形状校验不表示地址可投递。
- `ImageInfo` 字段私有，由构造器保证非零、单边和总像素限制。图片文件头
  解析通过 `ImageInspector` 端口由 infrastructure 实现；它不完整解码图片。
- Post、Page、User、Media、Tag、Category、Series 的 `reconstitute` 返回
  `Result`，检查各自的结构不变量，不静默规范化持久化标识。应用层将损坏
  快照映射为仓储错误。导入和新建仍应使用业务构造器。

## 状态与评论

媒体领域使用 set_deleted；仓储在媒体行锁内检查版本并同步审计。引用写入
共享媒体锁，允许保留同一来源的历史引用，拒绝新增软删除图片；数据库测试
验证回收站/恢复、CAS、并发引用、业务和审计整体回滚。物理文件不随软删除清理。
回收站文章由 Post 自身拒绝编辑、发布和撤回；恢复后才能继续编辑。

评论仓储接收 `NewComment`：正文为 `CommentBody`，游客身份携带
`CommentNickname`，账号身份携带用户 ID。账号昵称在事务内读取当前展示名，
去除控制字符、trim、截取 64 字，空值回退用户名，再经过同一昵称构造器。
审核使用 `ModerationAction::SetStatus(CommentStatus)` 或
`DeletePermanently`；HTTP 接口通过 `status` / `delete` 请求映射到这些操作。

分类防环、媒体引用保护、评论父子关系、作用域、幂等请求和 CAS 检查继续
留在仓储事务内。
