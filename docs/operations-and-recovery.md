# 备份与恢复

状态：工程建议，待实施及恢复演练验证。先覆盖 [13 表核心](database-design.md) 与实际部署的主题/静态资源；下文媒体、队列等流程仅在对应功能交付后适用。采用单站点、PostgreSQL、维护窗口恢复；备份频率、保留期、允许的数据丢失时间（RPO）和恢复耗时（RTO）在 M3 部署规格中确定，不承诺在线一致备份、零数据丢失或跨库无停机切换。

本文统一定义备份与恢复的操作边界，不重复内容保留、账号恢复和事件协议。相关规则见 [内容生命周期](content-lifecycle.md)、[身份与后台](identity-and-admin.md)、[扩展与数据](extensions-and-data.md)；方案取舍见 [ADR-0005](adr/0005-consistent-backup-and-recovery.md)。

## 1. 恢复单元与清单

数据库导出成功不等于站点可恢复。一次可用备份由同一 backup_id 关联下列材料，清单记录版本、数量、大小和校验和，包含完成标记：

| 材料 | 必须覆盖的内容 |
|---|---|
| PostgreSQL 一致性快照 | 当前 13 表：身份/OAuth、权限关系、文章/页面、分类树、系列顺序、标签关系与 settings；后续新增的媒体、审计、outbox 和任务也纳入同一恢复单元 |
| 本站静态资源/后续媒体对象 | 当前自托管 avatar/cover/logo 文件；未来媒体库的有效引用原件及必要派生文件，包括私有和回收站附件。外部 URL 对象不由本站备份保证恢复 |
| 主题 | 激活版本及仍被配置/历史激活记录要求保留的主题包、清单、设置和指纹资源 |
| 部署描述 | 应用构建标识、schema/导出格式版本、处理器版本、恢复所需的非敏感配置及存储映射 |
| 秘密恢复材料 | secret 引用对应的安全存储备份、解密所需密钥版本和恢复方法；秘密材料独立加密保存、独立控制访问，普通清单只记录引用与版本 |

页面缓存、请求缓存和外部搜索索引按派生数据重建，不作为唯一事实来源。外部统计服务的数据保留由提供商策略决定，本站备份不承诺恢复第三方历史报表。逻辑导入导出服务于迁移，不替代此恢复单元。

备份含私有内容和身份数据，必须限制访问并保护传输与存储；不能放在公开资源目录或可公开下载的对象前缀。本版无线上修订，整站备份不等于逐篇历史恢复；线上永久删除也不代表既有备份立刻清除，需明确备份到期规则。

## 2. 首期一致备份流程

1. 获取部署级维护互斥，阻止新业务写入，包括管理 API、上传、CLI、定时任务、主题激活及所有 worker；不能只禁用后台按钮。等待在途数据库事务、文件写入及外部投递退出或记录可核对结果。无法确认静止状态时终止本次备份，不写完成标记。
2. 停止会修改主库或对象的服务进程，保持维护页；暂停已交付的主题包回收、媒体删除、孤儿清理等任务。若有外部上传入口和有效上传授权，也必须停止写入或等到失效。记录维护开始时间和恢复所需的应用/schema 版本。
3. 在保持静止的窗口内导出数据库，按媒体/主题清单复制对象，并保存版本匹配的秘密恢复材料。数据库与对象存储不需要跨系统事务，但从生成清单到完成对象复制之间不得再修改或删除这些对象。
4. 校验清单、对象存在性、大小、校验和及秘密材料可用性。PendingDeletion 对象若已不存在，只有在确认无保留/公开引用且状态符合幂等删除规则时才可记为预期缺失；有效引用指向的对象缺失使备份失败。Staged 上传在清单中标记为未完成，恢复时不冒充 Ready。
5. 所有组成部分验证成功后写入完成标记，再解除维护并恢复服务。失败备份标记为不完整，保留上一份可用备份；只在恢复原部署状态确认安全后解除维护。

备份工具必须有失败清理与维护状态检查，不能因脚本异常让 worker 提前启动。在线备份或对象版本快照可以作为后续优化，但须先证明得到同等一致性，不能分别取两个任意时点的数据拼成完整备份。

## 3. 隔离恢复与重新开放

1. 停止或隔离旧部署，防止两个服务同时处理写入或投递。先在隔离环境恢复，默认关闭公开入口、外部投递和所有清理 worker；恢复模式由部署控制，不依赖可能已经回退的数据库开关。
2. 验证备份完成标记和清单，使用匹配的应用/schema 版本恢复数据库、媒体、主题和秘密材料。升级与恢复分开验证，不在恢复过程中盲目运行不兼容迁移。缺失必要密钥、有效引用对象或活动主题时保持隔离并报错。
3. 校验 slug 唯一及 Page 系统路由、分类树、系列位置、标签关系、公开条件、有效 Owner、settings/主题兼容性及秘密引用。媒体功能已交付时再核验资产状态和引用；Staged 上传转入补偿，PendingDeletion 在恢复删除前重新检查引用。
4. 当前会话和登录尝试只在进程内，停止旧进程并重建空存储，不能复用旧运行状态。以后若加入持久会话、邀请或初始化凭据，恢复时一并撤销，防止备份回退使旧凭据重新有效。操作者核对 Owner、角色、settings.oauth 与秘密引用，必要时执行带运维日志的离线账号恢复，不开放公开初始化入口。
5. 丢弃旧缓存并建立新的缓存命名空间，不能复用可能与备份外状态碰撞的 generation。事件系统如已接入，为新产生的事件建立新的 stream_epoch，避免恢复后重复使用旧版本序列；保留旧事件的原始身份和世代。搜索从恢复主库构建新索引命名空间及消费水位，完成校验后再切换；旧索引水位可能高于恢复库，不能直接接着消费旧命名空间。
6. 按下一节分类核对队列，验证登录、读取、编辑、发布、草稿隔离和媒体访问。完成恢复检查与记录后，再逐项开放写入、worker 和外部投递。演练环境始终禁止向生产接收端投递。

## 4. 恢复后的任务策略

| 任务 | 恢复策略 |
|---|---|
| 搜索同步 | 在新索引中从当前主库重建并建立匹配水位，切换前保持写入暂停；重新开放后只向新索引消费 |
| 媒体/主题清理（交付后） | 重新核验当前引用、保留期与状态，恢复租约并验证幂等后启动 |
| Webhook、业务通知 | 默认隔离恢复出的投递记录；核对外部回执后决定跳过或重放并审计。维护内容状态的接收端先确认新的事件世代与基线，再开放新投递 |
| 非关键访问统计 | 不批量回放旧访问事件，防止重复计数；按提供商契约恢复新采集 |

外部接收端可能已经处理了备份之后的事件，而恢复库中没有这次成功记录。重放必须沿用原 event_id，接收端去重仍是必要条件；确认跳过、继续核对和重放都是显式状态，不能伪造为投递成功。恢复点之后丢失的本地事件也无法仅凭备份补回，不承诺数据库回滚等于外部副作用回滚。

租约重置只能在旧 worker 已停止且外部在途请求已核对后进行。仅等待本地租约过期不能证明远端请求停止；结果不明的外部任务继续隔离。恢复边界和重放记录作为新的运维审计保存。

## 5. 交付与验收

M3 交付核心数据库/资源清单、维护备份、隔离恢复和身份核对；M4 加入媒体、搜索/Webhook 时补齐对应恢复流程；M5 对拟上线的全部能力执行完整演练。按实际交付范围验收：

- 备份期间尝试上传、发布及对象删除，验证写入被阻止；强制中断备份，验证不产生可用完成标记。
- 在空环境恢复公开/私有文章、草稿、Page、Post 回收站、分类树、系列顺序、权限和 settings；校验自托管资源与主题。媒体库交付后另验证共享附件和私有访问边界。
- 模拟对象、主题或密钥缺失，恢复保持隔离并明确报告缺失项；验证旧会话、邀请、登录尝试及后续可能引入的初始化凭据不恢复有效。
- 模拟外部已投递成功但备份中仍为待投递，确认恢复不会自动重复发送，受控重放保持事件 ID。
- 对恢复前较新的搜索索引和缓存执行命名空间重建，确认恢复后的撤回、发布及媒体引用变化按新状态生效；验证新事件世代内相同数值版本可正常消费，旧世代迟到请求不会覆盖新状态。
- 记录备份大小、维护时长、恢复耗时和实际可恢复时间点，与部署前确定的 RPO/RTO 比较；未达到目标不能标记恢复验收通过。
