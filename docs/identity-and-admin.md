# 身份、认证与后台安全

本文规定当前账号、权限、认证与会话的边界。HTTP 路由、请求格式和业务错误码见 [管理 API](admin-api.md)，账号初始化及 CLI 操作见 [开发指南](development.md)，Cookie、OAuth 秘密和部署参数见 [配置参考](configuration.md)。

新基线已采用独立 `users.auth_version` 与 `sessions.auth_version` 快照；`users.version` 用于资料及关联编辑。资料编辑、角色变化保持登录，权限逐次重读；仅 active 且未软删除账号可以登录。后台已提供个人资料和账号启用/停用；账号删除入口尚未提供。详见[身份规则](database-design.md#2-身份与权限)与[会话表](database-design.md#7-持久会话)。媒体及头像入口已切换新表；头像变更保持登录，详情见[媒体生命周期](content-lifecycle.md)。

## 1. 可信身份与入口

公开站点使用 SSR，后台 SPA 位于 `/admin/`，管理接口位于 `/api/admin/v1/`，认证入口位于 `/auth/`。SPA fallback 只覆盖后台子树。管理响应和受权预览使用 `Cache-Control: no-store`。

用例只接受由服务端会话或受控本机 CLI 解析出的 `Actor`。用户 ID、有效权限和文章归属从服务端读取，不能相信请求提交的作者或权限列表。前端路由守卫和禁用按钮用于提示，最终授权在后端执行。Post/Page 管理操作以 UUID 定位；公开阅读以 slug 定位，规则见 [内容生命周期](content-lifecycle.md)。

浏览器持有不透明会话 Cookie，设置 `HttpOnly`、`SameSite=Lax`。HTTPS 公开地址强制 Secure，使用 `__Host-blog_session` 且不接受旧名称回退；HTTP 开发使用 `blog_session`。HTTPS 用户从旧版本升级需重新登录。已认证写请求要求会话对应的 `X-CSRF-Token`，退出也受此保护。当前 Origin 检查的实际边界是：

- 有 `Origin` 时，与 `http://<Host>` 或 `https://<Host>` 比较，忽略大小写；跨源请求拒绝。
- 缺少 `Origin` 时放行；因此当前并未强制所有客户端发送 Origin，也未按外部站点配置强制校验协议。
- 匿名密码登录尚无会话 CSRF token，使用上述 Origin 检查和 Cookie 策略。

`GET /api/admin/v1/me` 确认 Cookie 对应的会话失效时，返回 401 并清除该 Cookie，使后续游客评论可以使用匿名身份。账号或权限存储故障返回内部错误并保留 Cookie，不将查询失败视为会话失效。

客户端应按稳定的 `code` 处理错误，并在报障时保留 `x-request-id` 响应头；应用错误体也包含 `request_id`。错误码、非 JSON 拒绝和当前编号不一致的例外集中在 [管理 API](admin-api.md)。

## 2. 账号与权限模型

用户可同时拥有多个角色，有效权限取角色权限的并集；没有用户直授权、角色继承、deny 优先级或策略脚本。权限目录由 [`PERMISSION_REGISTRY`](../crates/application/src/identity.rs) 注册并随初始化同步，普通管理入口不能创建任意可执行权限 key。

内置角色的当前范围如下，角色组合仍取权限并集。

| 角色 | 默认权限范围 |
|---|---|
| admin | 全部已注册权限，包括文章/页面永久删除、OAuth 维护、审计读取和管理员管理 |
| editor | 创建并管理全部文章；页面、分类、标签、系列管理；媒体 read/upload/delete/delete_any |
| author | 创建文章及本人文章 read/update/publish/unpublish/delete；媒体 read/upload/delete |
| reader | 发表评论及管理本人资料；无内容管理权限 |

具体授权以动作检查为准，角色显示名称不能替代权限判断：

- 文章 own 权限须匹配存储的 `author_id`，对应 any 权限覆盖本人及他人文章。后台提供本人/全部及作者筛选，`post.read_any` 可管理停用或软删除账号留下的内容，不要求该作者仍能登录。预约沿用发布权限，归档、取消预约和解除归档沿用撤回权限；回收站恢复沿用 `post.delete` / `post.delete_any`，永久删除另需 `post.purge`。
- Page 无作者，使用站点范围的 `page.*` 权限。预约使用 `page.publish`，归档使用 `page.archive`，取消预约或解除归档使用 `page.unpublish`；删除/恢复使用 `page.delete`，永久删除另需 `page.purge`，默认仅授予 Admin。
- 分类、标签、系列的管理分别需要对应 `*.manage`；系列成员列表逐篇检查读取权限，整体重排逐篇检查修改权限。目录读取对已认证用户开放，关联文章仍按文章权限检查。
- 媒体库读取、上传、本人删除和任意删除分别授权。所有图片链接独立公开；使用位置权限、软删除与物理保护见 [内容生命周期](content-lifecycle.md)。
- 自助头像不需要额外权限；站点 logo 保存需要 `settings.manage`。上传图片另需 `media.upload`，引用现有图片仍受附着规则检查。
- 后台「任务管理」的读取、HTML 预检、启动、计划、取消和重试复用 `settings.manage`，默认仅 Admin 拥有。仅支持 HTML 重建、保留期清理和预约发布三类固定任务；不会因此授予文章编辑或审计查询权限，`audit.read` 仍独立检查。预约发布固定启用和 30 秒周期不可在后台改写。

数据库能够表达自定义角色，但当前管理功能只提供角色目录和用户角色分配，没有角色定义的创建、改权或删除流程。内置角色 code 由可信种子维护；当前角色 DTO 的字段仍名为 `slug`。

管理员可在后台「站点设置 → 账号与评论」开放注册，默认关闭。注册必须填写用户名、邮箱和密码，昵称可选；新账号固定为 reader，可评论及编辑本人资料，不能发表文章。登录支持用户名或邮箱，两种标识共享账号限流。首次 OAuth 登录自动注册、邀请及邮箱找回尚未实现。[首次安装向导](installation.md)通过终端安装码在空库中原子初始化权限目录、内置角色、首个 Admin、本地密码、完成标记和审计；安装后关闭该入口。受控 CLI 仍可分步创建账号、设置密码或绑定已核对的外部身份、分配角色。用户名和邮箱的当前规范化、唯一性见 [数据库实现参考](database-current.md)。

## 3. 角色委派与最后 Admin

角色分配和移除需要 `role.manage`。授予角色时，该角色的完整权限集合必须包含于调用者的权限集合，不能借分配角色提权。授予或移除 `admin` 另需 `admin.manage`；Admin 身份来自受保护的 `admin` 角色分配，不从显示名或“拥有全部权限”推导。

实际增删角色分配会递增目标用户的 `users.version`，保持 `auth_version`；原会话继续有效，后续请求立即读取新权限。重复分配已有角色、移除不存在的分配不递增版本。账号管理列表的 `is_last_loginable_admin` 根据全站计数产生，不能由前端按当前分页推断。

当前“可登录 Admin”的存储判定是：账号 active 且未软删除、持有 `admin`，且有本地密码哈希或至少一条与当前 OAuth 提供商命名空间匹配的外部身份绑定。OIDC 按精确 issuer 匹配，GitHub 使用固定平台命名空间；失效配置留下的绑定不计为备用登录方式。移除最后一位满足此条件的 Admin 时拒绝操作。角色分配/移除、外部身份解绑、受保护的密码清除和 OAuth 配置保存使用同一把身份事务排他锁；解绑与清除还必须保留该账号至少一种有效登录方式，防止两个并发操作各自认为另一种方式仍在而全部删空。

账号启用/停用也取得这把排他锁，在锁内重新读取操作者当前账号权限、目标 Admin 角色及编辑版本。普通账号需 `user.manage`，操作 Admin 另需 `admin.manage`；停用最后可登录 Admin 被拒。允许停用本人，成功后本人会话失效。实际状态改变同事务递增 `version/auth_version`、删除会话并追加审计；启用也递增认证版本，停用前或停用期间迟到的旧会话不能在启用后复活。相同状态且版本匹配时无变更，旧版本始终冲突。密码、外部绑定、角色、文章与独立公开媒体均保留；启用不等于恢复软删除账号。

规则实现位于 [identity/policy.rs](../crates/application/src/identity/policy.rs) 与 [login_methods.rs](../crates/domain/src/identity/login_methods.rs)，不依赖数据库或运行时。账号状态计划按权限、版本、幂等依次判断；停用 Admin 的计划要求在锁内进一步复核全局可登录 Admin 数。密码清除和外部身份解绑共用登录方式规则。规则提取不改变上述身份锁协议，拒绝或无变化时不递增版本、不撤销会话、不追加变更审计。

这些保证有明确范围：配置匹配只判断命名空间，不探测提供商在线状态、client secret 是否正确或 `secret_ref` 环境变量是否存在；维护 client_id、secret_ref 或外部服务时仍须核验登录。普通内容写入没有统一取得身份共享锁，不能把“下一次会话验证拒绝旧版本”解释为已授权的在途请求也会被取消。当前也没有独立的原子所有权转移或通用近期重新认证机制。

## 4. OAuth 与 OIDC

当前适配通用 OIDC 和 GitHub。OIDC 身份键使用精确 issuer 与 `sub`，GitHub 使用固定平台标识与稳定用户 ID，不使用可改名的 login 或邮箱作为身份键。相同邮箱不会自动合并账号；未预先绑定的外部身份不能登录。

提供商的非敏感配置存入 `settings.oauth`，秘密由 `secret_ref` 指向部署环境。维护配置和绑定需要 `oauth.manage`，不受普通 `settings.manage` 覆盖；当前通过受控 CLI 操作，没有浏览器绑定界面。操作者须核对稳定外部 ID。修改 OIDC issuer 会改变身份命名空间，不能假定原绑定自动迁移。

OIDC issuer 必须是可解析的精确 HTTPS URL，不允许凭据、查询或片段。发现文档的 authorization/token/JWKS/userinfo 端点必须为不带凭据和片段的绝对 HTTPS URL；允许合法跨域端点。身份客户端（含 GitHub）仅访问 HTTPS，不自动跟随重定向，以免 307/308 转发带 client_secret 的请求体。此策略不等于完整的 SSRF 网络隔离：IdP 仍需可信，若部署要求禁止内网目标，应在出站代理或防火墙限制地址和 DNS 解析后的目标。

目录读取仍对已认证会话开放。标签、分类只返回公开文章计数；系列 `post_count` 仅在调用者具有 `post.read_any` 时返回数字，否则为 null，公开成员计数保持可见。创建和更新（含幂等更新）的系列响应也遵循同一规则，自定义 `series.manage` 不隐含文章读取权。


提供商配置读取返回列表与分组版本；缺失组版本为 0。保存必须带读取时的版本，先检查版本再判断同值：旧版本即使内容相同也冲突；匹配版本且同值不增版、不记变更审计，空组保存空列表仍保持版本 0。CLI `add-oidc/add-github` 内部读取并提交该版本，没有新增版本参数；并发冲突须重新执行，不会静默丢失另一次更新。

减少配置覆盖的身份命名空间时，只要已有 Admin 角色分配，变更后就必须至少保留一位符合上述谓词的可登录 Admin，否则设置、版本和审计同事务回滚。尚无 Admin 的初始化允许配置变更。账号列表的外部登录方式、密码清除、解绑和角色保护复用当前配置匹配规则；不存在的绑定解绑为无变化，清除未配置的残留绑定不算减少有效登录方式。配置更新不主动撤销现有全部会话。

浏览器登录由后端完成授权码交换：

1. 生成一次性 state 和浏览器绑定 Cookie。OIDC 另生成 PKCE S256 verifier/challenge 与 nonce；当前 GitHub 适配使用 state，不发送 PKCE。
2. 服务端保存提供商、redirect URI、回跳路径及所需校验材料。尝试存储在进程内，TTL 为 10 分钟，容量上限 1,000。
3. 回调先核对浏览器绑定，再原子消费 state；随后检查提供商和有效期。绑定不匹配的请求不会消耗真实尝试，已消费的尝试不能重放。
4. 在数据库事务外交换 code。OIDC 校验签名、issuer、audience、必要的 azp、有效期和 nonce；GitHub 从受信用户接口取得稳定 ID。
5. 交换完成后重新读取提供商配置，确认仍存在且 client ID 未变化；原子读取外部身份绑定、活跃账号及当时的 `auth_version`。读取当前权限后，账号认证版本必须仍与此快照一致，签发只能使用快照中被证明的版本。解绑、改密或明确撤销发生在两次读取之间时拒绝登录；发生在签发之前或之后时，旧版本会话无法通过认证，不能把旧身份证明附到撤销后的新版本。网络交换仍在事务及锁外执行。回跳只允许经过校验的本站相对路径。

第三方 access/refresh token 不持久化，client secret、PKCE verifier 和第三方 token 不返回 SPA 或写入浏览器持久存储。公开提供商目录只返回 ID、展示名和类型。

外部身份的 `(provider, subject)` 为复合主键，冲突不能覆盖原绑定，不持久化外部邮箱；端口中的 `provider_user_id` 映射至 `subject`。绑定和解绑在身份事务锁内递增 `version/auth_version` 并删除该用户全部持久会话。解绑不能移除最后一种登录方式；不存在的绑定按无变化处理。OAuth 维护用例与浏览器登录用例分开装配，不依赖主题、静态资产或站点地址。

## 5. 本地密码

密码使用 Argon2id PHC 字符串，当前参数为内存 19,456 KiB、迭代 2、并行度 1、输出 32 字节、随机盐 16 字节。哈希与校验在阻塞线程池运行，并以信号量限制最多 4 路并发。凭据通过独立端口读写，不进入普通 `UserSnapshot` 或管理列表。

新密码须满足 12–128 个字符、不得包含用户名，并拒绝常见及规律口令。受控 CLI 支持隐藏输入或标准输入，不提供会进入进程参数的明文密码选项；操作方法见 [开发指南](development.md)。

密码登录对用户名不存在、密码错误及账号停用返回相同的凭据错误，未知账号也执行一次虚拟哈希校验。哈希参数与当前策略不同时，在成功登录后尝试重新生成；替换使用条件写入，只能覆盖刚验证的旧哈希。签发会话前复核当前凭据和账号版本，避免并发重置后继续使用旧密码建立有效会话。

自助改密的规则是：

- 已启用密码时须提供当前密码，校验与登录共享失败预算；尚无密码的 OAuth 用户可凭有效会话设置初始密码。
- 新凭据使用 compare-and-swap 写入，旧哈希必须仍等于刚校验的值；首次设置时必须仍为空。并发变更返回版本冲突。
- 写入在同事务递增 `version/auth_version` 并删除既有持久会话，返回本次产生的 `auth_version`，随后为当前浏览器签发绑定此版本的新会话和 CSRF token。不能借用后续重置产生的版本。
- 当前密码错误不代表会话掉线，前端保留登录态并提示重新认证失败。

管理员设置、重置或清除密码只通过受控 CLI，要求 `user.manage`。这些操作会撤销全部会话。清除密码与解绑外部身份共享最后登录方式保护；需要更换密码时直接设置新值。当前没有邮件重置或自助找回，失去全部可用凭据需由持有部署权限的运维恢复。

## 6. 会话与失败限流

生产会话持久化在 PostgreSQL，浏览器令牌为 256 位随机值，数据库只存 SHA-256 摘要。默认空闲期限 2 小时、绝对期限 7 天、总容量 10,000；访问刷新最后活跃时间，不延长绝对期限，容量满时先清过期会话再淘汰最久未活跃项。

管理请求只做一次会话存储校验，同时取出 CSRF 信息和 Actor。PostgreSQL 先核对账号 active/未删除、`auth_version` 快照和空闲/绝对期限，全部通过才刷新活跃时间；Actor 再读取当前权限并复核认证版本。改密、绑定/解绑、明确撤销全部登录使旧快照失效，即使旧会话行尚未清理或并发晚到也不能认证。资料和头像更新只递增编辑版本，角色变化也不撤销登录。

会话能跨进程读取和撤销，重启服务不会清空。数据库备份也包含旧会话，恢复后应显式撤销，流程见 [运行与恢复](operations-and-recovery.md)。OAuth 一次性尝试和密码限流仍在进程内，重启会清空；共享会话不等于认证全过程已经支持多实例部署。

密码登录与自助改密按以下维度限流：

| 维度 | 失败预算 | 锁定时间 |
|---|---|---|
| 账号（用户名和邮箱共享） | 15 分钟内 5 次 | 15 分钟 |
| 可信代理解析后的来源地址（无法解析时回退 socket 对端） | 15 分钟内 50 次 | 15 分钟 |

额度在昂贵的哈希校验前预占，在途请求与已确认失败共享上限；请求取消或未完成验证时归还预占。锁定期间的拒绝不延长锁定。成功验证清除账号维度的历史失败，但不清除来源地址的历史失败，避免用一个已知账号刷新地址预算。

限流主体最多 10,000 个，满时淘汰空闲项；全部在途时拒绝新增主体而不突破容量。来源地址与评论/审计共用可信代理解析规则：只有 `BLOG_TRUSTED_PROXIES` 指定的精确 socket IP 可以提供 `X-Forwarded-For`，从右侧剥离可信代理；不可信对端的转发头被忽略。可信代理头缺失、非法或没有可识别客户端时，限流回退 socket IP（审计仍留空），避免通过坏头绕过来源额度。代理须正确重建或追加链路，并限制客户端直接访问应用端口。未配置可信代理时，同一代理后的用户仍共享来源桶；共享出口 NAT 用户也会共享桶。登录与自助改密使用相同规则。多实例认证仍未交付，边界见 [路线图](product-roadmap.md)。

## 7. 后台与可观测边界

当前后台提供文章、页面、分类、标签、系列、媒体库、用户角色分配与账号启停、站点设置、个人资料、自助改密和自助头像。已发布正文保存后立即影响公开内容，不能呈现为另一份待发布草稿；无修订表，也没有历史恢复界面。角色定义编辑、外部身份绑定、邀请及密码找回不在当前后台能力内。

独立 `/admin/tasks` 提供三类固定任务的最新状态、计划和历史。HTML 可立即执行或安排未来的一次性计划，保留期可手动执行或启用默认关闭的每日周期，预约发布保留固定 30 秒自动检查。短请求持久接受任务，刷新或关闭浏览器不会取消执行；queued 请求跨重启保留，运行中任务中断或租约过期后需人工以新 ID 重试，每类终态历史最多 500 条。HTML 每批 100 条、最多 100 批，不增加业务编辑版本或改变更新时间；可信启动者与来源 IP 随执行进入审计。后台服务之间通过租约及业务事务核验协调，独立 CLI 仍使用原有 CAS 与业务锁、不加入队列。恢复模式或数据库隔离时任务状态可读、变更与执行禁止；操作和受限维护账号边界见[运维](operations-and-recovery.md#后台任务管理)。

编辑器的未保存提醒覆盖菜单、屏内链接、退出登录、刷新/关闭，以及后台浏览器前进、后退。取消历史导航保留原编辑器与输入，确认后才切换页面；保存响应仍保留等待期间的新输入。此机制不提供自动保存或崩溃恢复，具体边界见[后台开发约定](admin-development.md)。

`PUT /api/admin/v1/me/profile` 已支持本人展示名和纯文本简介更新，必填编辑版本，冲突返回 409；成功变更与脱敏摘要在同事务写入 `audit_logs`。后台 `/admin/profile` 已接入表单、未保存提醒和冲突处理；冲突保留输入，明确重新加载后才使用新版本。用户创建、状态启停、密码与 OAuth 登录方式变更、明确撤销全部会话、角色分配及权限目录同步也已接入事务审计；操作者与目标用户分开记录，CLI/系统任务使用空 actor，摘要不含邮箱、哈希或 OAuth subject。审计失败连同认证版本和会话删除一起回滚。普通会话活跃刷新/退出不作为业务变更审计；HTTP 写入通过显式上下文记录经可信代理规则提取的 IP，`/admin/audit-logs` 已提供只读查询，独立要求 `audit.read`（默认授予 admin，其他角色需要单独获得此权限）。运行账号只追加和独立保留期维护权限见[运维](operations-and-recovery.md)。

访问日志记录请求 ID、method/path、状态、耗时和经服务端验证的 actor；不记录查询串、Cookie、密码、授权码或 token。预期 4xx 记 info，5xx 记 warn。它能关联请求结果；上述成功业务变更另由事务审计记录，不能把访问日志当作事务审计保证。

## OAuth 配置读取校验

OAuth 提供商的单项规则与集合内 ID 唯一性由应用层 `oauth_config` 统一校验，维护输入和持久化读取复用这些规则。认证用例在使用配置前也验证端口返回的数据；缺少 OIDC issuer 等损坏配置在联网或绑定写入前返回错误，不 panic，不静默跳过提供商。issuer 保留原值用于精确身份命名空间匹配，不自动规范化。

非法维护输入返回输入错误；数据库内的损坏配置返回存储错误，HTTP 仅展示通用内部错误，诊断日志包含设置分组与失败规则，不输出整份配置或秘密值。损坏配置也会阻止依赖该设置的维护操作，需要管理员核对并修复数据库记录后重试；系统不会通过自动删除提供商绕过版本、审计或最后 Admin 保护。

注册接口为 `GET/POST /auth/register`，管理开关为 `GET/PUT /api/admin/v1/access-settings`（`settings.manage`，更新携带 version）。游客评论开关独立于注册开关，默认关闭；关闭时需登录，开启时允许匿名提交，仍遵守全站/文章评论开关和审核规则。设置与注册提交在数据库事务内复核；公开注册不能指定角色。旧 owner 角色由新增迁移合并到 admin，保留已有用户和授权，继续保护最后一个可登录管理员。
