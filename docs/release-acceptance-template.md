# 上线验收记录模板

将本文复制为一次候选版本的验收记录，保存在部署方的受控证据目录。本文不记录完成状态；交付与生产验收进度只在[路线图 M5](product-roadmap.md#3-里程碑与验收入口)维护。`待填写` 不是通过条件；阈值由部署方在运行前确定，原始结果不可用结论性描述替代。

| 配置版本或校验和、秘密材料保管位置 | 待填写；证据中不保存秘密值 |

| 主题、列表分页深度、作者数与后台操作分布 | 待填写 |

| 对象 | 目标 / 上限 | 实测值 | 原始证据 |

| 系列重排 P95 / P99、错误率；409 单列 | 待填写 | 待执行 | 待提供 |
| readiness 成功率、P95；池占用、内存峰值 | 待填写 | 待执行 | 待提供 |
| 过载与数据库故障后的恢复时间、告警到达时间 | 待填写 | 待执行 | 待提供 |
| 全量备份频率、保留期、实际 RPO / RTO | 待填写 | 待执行 | 待提供 |
| 迁移、HTML 重建、停写及重新开放总耗时 | 待填写 | 待执行 | 待提供 |

例如可讨论“预计峰值的 2 倍、持续 30 分钟”作为某轮压力场景；这只是选择负载的方法，不能替代实际请求速率、数据规模和可接受延迟的确认。原生压测客户端与服务共机时须另记客户端 CPU 占用。HTTP 指标测到响应头；压测客户端测到响应体读完，两者不得混用。

使用[容量工具](public-read-capacity.md)可生成随机专用测试库上的读取/多客户端保存/系列重排报告，并配置系列成员规模观察 CAS 与事务锁竞争。409 单列为冲突，工具不把它计为系统错误；验收必须同时检查成功操作数和冲突率，不能只看 `passed`。工具采用闭环并发客户端，不证明固定外部到达率下的容量；没有模拟不同账号权限变化、评论持续提交、预约任务堆积或复杂主题。目标范围包含这些场景时，须另设负载并保存结果。目标规格验证仍使用专用测试资源，不能把工具指向真实站点数据库。

## 真实浏览器关键路径

| 场景 | 通过条件 | 浏览器 / 视口与证据 |
|---|---|---|
| 登录与身份切换 | 正常登录；撤权后拒绝写入；不向另一账号展示前一账号本地草稿 | 待执行 |
| 编辑与恢复 | 保存期间继续输入不丢失；刷新后明确恢复/忽略候选；两个标签同时编辑时各自保存/删除不清除另一窗口副本；存储不可用时仍可编辑并看到提示 | 待执行 |
| 预览与冲突 | 预览不改服务器正文/版本；两窗口编辑触发 409 并保留本地输入，可比较后选择下一步 | 待执行 |
| 发布与撤回 | 带未保存修改撤回时不先发布修改；公开详情、目录、feed、sitemap 同步退出公开范围 | 待执行 |
| 媒体、评论与回收站 | 图片上传插入可读；评论提交/审核；Post/Page 删除恢复不自动上线；永久删除授权有效 | 待执行 |
| 两套主题与真实域名 | 移动端无影响阅读的溢出；键盘可达操作；深浅色、代码排版、canonical 与资源地址正确 | 待执行 |

记录浏览器版本、桌面/移动视口和操作步骤；失败保存截图与 trace，并关联修复后复验。组件测试和 HTTP 验收分别覆盖交互逻辑与接口，不替代真实浏览器布局、焦点、存储和资源加载。

## 故障与恢复证据

按[部署](docker-compose.md)、[恢复](compose-backup.md)及[迁移顺序](schema-migrations.md#部署与恢复顺序)执行。记录停写覆盖的 HTTP、CLI 和任务，故障开始、告警、恢复、核验和开放流量的时间；从实际远端副本在空环境恢复，核验数据库引用与媒体原件、会话撤销、预约任务隔离及秘密材料。分别保存缺失秘密、损坏备份、中断和重试的预期失败结果。
