# 扩展设计候选

本文保存后续扩展方案与启用条件。已实现的可信编译期[插件机制](plugins.md)提供独立管理、正文和前台资源钩子，内置 Markdown 增强支持公式、Mermaid 与后台正文预览，Umami 插件支持公开页面采集和外部报表链接；没有任意代码安装器或插件执行沙箱。其他功能状态见[路线图](product-roadmap.md)，主题契约见[主题与渲染](themes-and-rendering.md)。当前只有 PostgreSQL，没有外部搜索、统计报表 API、Webhook 或 outbox。

## 1. 扩展边界与启用条件

| 候选能力 | 机制 | 启用前必须明确 |
|---|---|---|
| 搜索、统计、邮件、对象存储 | application 端口与 infrastructure 适配器 | 提供商、数据范围、失败降级、权限及恢复责任 |
| 内容事件 Webhook | 提交事务中的 outbox 与独立投递记录 | 事件协议、签名、接收端去重、重试与重放 |
| 声明式扩展设置 | 版本化配置 Schema 与受控表单 | 字段校验、秘密引用、读写/启停授权 |
| 第二种关系数据库 | 独立适配器与迁移 | 等价事务语义、契约测试、迁移与备份恢复 |
| 第三方执行代码 | 待评估的版本化 SDK 与隔离运行时 | 确有受限入口无法满足的需求，再设计能力授权、资源预算和隔离 UI |

模板宿主函数是核心提供的公开只读 API，不是主题上传执行代码的入口。适配器随可信应用构建发布；管理员只能配置已安装的 provider。认证判定、核心事务、任意 SQL 和同步内容修改钩子不作为开放扩展点。

未来连接配置可包含 provider、启用状态、Schema 版本、非敏感参数、secret 引用和健康状态；创建、测试、启用、暂停、删除及历史保留分别定义。秘密值留在部署秘密存储，不能复用当前 `settings.site` 接口接收任意连接配置。权限 key、存储模型和审计随功能一起确定，不预建空聚合或占位表。

出站目标须约束地址、DNS 和重定向，私有服务通过部署白名单开放，连接测试使用相同限制。服务主体不继承配置者的 Admin 权限，第三方脚本不进入后台同源 SPA。当前代码插件采用可信编译期扩展；第三方上传、WASM 隔离和 Rust 动态库 ABI 均未提供。

## 2. 内容事件与可靠投递候选

内容提交、事件快照与 outbox 必须在同一事务中写入。网络发送放在提交后，由独立生命周期的 worker 执行；不能把内存通知当作可靠投递。下面是设计输入，尚未对应数据库表或已冻结的外部协议。

| 字段 | 作用 |
|---|---|
| `event_id` | 唯一事件身份；重试和手动重放沿用原值 |
| `stream_epoch` | 恢复世代；隔离备份回退前后的版本序列，正常重启不变 |
| `content_type` + `content_id` | 内容身份；永久删除后不复用 ID |
| `aggregate_version` | 同一世代内的提交先后；允许跳号 |
| `payload` | 事件产生时冻结的必要状态；不能事后用新正文冒充旧内容 |
| `event_type` / `schema_version` | 事件语义及格式演进 |

发布 v10、撤回 v11、再发布 v12 即使乱序抵达，也必须保留 v12 的结果。消费者不按 UUID、时间戳或领取顺序推断提交顺序，不等待连续版本。正文历史有保留上限，也不覆盖全部关联操作，需要原始内容的事件仍必须自行保存快照。

消费水位按 `(stream_epoch, content_type, content_id)` 隔离。撤回和永久删除使用带版本的 tombstone；删除后仍保留覆盖可重放窗口的消费水位，避免迟到旧事件重建内容。超出窗口改走当前状态重建。目录名称等独立变化需要对应投影版本或重建协议，不能只比较未改变的 Post.version。

适配器需要远端条件写入，或能保证远端完成顺序的逐内容串行协议。仅在请求发出前比较本地水位不够：租约重领、超时后仍执行的旧请求仍可覆盖新值。未知结果先核对，不标记成功。恢复时建立新世代与接收端基线，隔离旧投递；重放保留原事件身份和世代，不能把数据库回滚理解为外部副作用回滚。

Webhook 另需时间戳、签名、投递记录、重试上限、死信及显式重放权限。不承诺恰好一次网络投递。统计可按契约丢弃非关键事件；内容索引和业务通知不能无记录丢弃。

## 3. 搜索与统计候选

搜索提供商须先用实际中文内容验证检索质量、授权过滤、运维成本和重建能力。候选架构是内容提交 → outbox → 索引任务 → 适配器，公开查询与后台查询使用不同授权范围；搜索不参与内容发布事务。

公开索引只接收当前公开内容。结果返回前用主库当前可见性过滤，并据此构造标题、摘要和链接，避免外部索引继续泄漏已撤回摘要。消费者若合并事件同步最新状态，应一致读取内容、关系和版本；不能给旧正文套上新版本号。需支持全量重建、索引命名空间切换、同步状态与失败重试。服务停机时正文仍可阅读，搜索明确报告不可用，不以空列表掩盖故障。

统计分开设计事件采集和后台报表查询，明确 PV/UV、时区、机器人过滤、延迟及保留期。事件异步有界发送，统计故障不阻塞阅读。默认不包含 token、Cookie、敏感查询参数或草稿；IP/Cookie 的采集策略由部署确定。报表权限、凭据和提供商访问约束需同时交付，不能用公开报表链接代替授权。

## 4. 多数据库候选

多数据库指一次部署选择一种关系数据库，不表示双写、跨库事务或不停机切换。SQLite/MySQL 只是候选；当前[持久化模块](../crates/infrastructure/src/persistence/)按业务拆分，尚无这两种驱动或迁移目录。

新增后端时才决定 Cargo feature 与配置选择，每个后端维护自己的 SQL 和迁移。不得把 SQLx Any 或相似 SQL 语法当作业务兼容。验收至少覆盖：

- 稳定 ID、UTC 时间精度、JSON/NULL、排序与唯一键规范化。
- 外键、唯一约束、版本 CAS，以及内容、关系与已启用 outbox 的同事务提交。
- 分类防环、系列多对多排序的锁序与版本条件、媒体引用及审计提交的等价实现，按[已采纳目标设计](database-design.md)验证；目标不再要求系列位置唯一。不能假定 PostgreSQL advisory lock 在其他后端存在。
- 各后端的并发、任务领取、迁移失败处理与备份方案。SQLite 还需逐连接启用外键并明确单机部署边界。
- 共享仓储契约、用例集成、迁移升级、冲突与恢复验证；性能容量单独报告。

跨库迁移另行设计版本化逻辑导出/导入：暂停写入，迁移内容、身份、权限、配置及媒体清单，核验后切换；会话失效，秘密材料独立迁移。逻辑导出不替代[完整备份](operations-and-recovery.md)。

## 5. 启用前验收门槛

后续能力需进入[路线图](product-roadmap.md)的明确交付范围，再完成自身验收，不能因本文列出方案就宣称支持。

- 连接越权、禁用后的行为、出站地址限制和秘密脱敏。
- 外部停机、配额、超时、退避、并发与统计背压。
- 同内容乱序/重复事件、永久删除后的迟到事件、租约重领与未知远端结果。
- 备份回退后的新世代、索引重建、旧投递隔离及保留事件 ID 的重放。
- 配置删除后的数据保留；新增后端或代码插件各自的迁移/恢复和隔离验证。

任务可以先随主进程部署，但生命周期应独立于 HTTP 请求；是否拆出 worker 进程由实际负载决定。
