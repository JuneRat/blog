# 内容、路径与媒体生命周期

本文定义当前业务行为：单份正文、发布与删除、内容关系、公开地址和媒体来源。字段与数据库约束见[当前数据库实现](database-current.md)，权限见[身份与后台](identity-and-admin.md)，请求格式见[管理 API](admin-api.md)。

内容、目录和媒体已适配[数据库设计](database-design.md)：系列多对多、Post/Page 定时发布及回收站、归档可退草稿、预约即锁 slug，以及媒体链接独立公开、软删除保留文件。评论、隔离恢复与正式媒体显式清理也已接入。

## 1. 当前正文与资源身份

Post 和 Page 各保存一份 Markdown 源文。Post 有作者、摘要、分类、标签、系列和封面；Page 是无作者、无这些关联的独立页面。

保存已发布内容会直接更新线上，包括正文、标题、关联和可见性。服务器没有编辑副本、修订历史或逐篇撤销；需要保持修改私密时先撤回为草稿。后台本机恢复副本只保存在浏览器，不等于服务器自动保存或独立发布副本。草稿允许标题和正文为空。

Post/Page 编辑器在用户身份和目标内容确认后，按账号、类型、UUID（新建为 `new`）、标签 ID 和页面实例 ID 保存未提交输入到 `localStorage`。标签 ID 放在 `sessionStorage`；额外的页面实例 ID 避免复制标签继承相同标签 ID 后互相覆盖。重新进入时可查看本标签之前、其他标签或旧 v1 格式的恢复候选，按时间与基线版本明确选择。恢复将候选复制到当前窗口，只回填编辑器，不发送保存请求，也不删除源副本；旧副本保留原 CAS 版本，服务器变化时须对比后处理。

连续输入按固定 400ms 窗口合并写入本机；离页、隐藏和编辑器卸载时同步补写最新表单值。成功提交、删除副本和新稿获得 UUID 会取消旧待写任务，避免提交后的旧槽再次出现。恢复克隆立即写入本机，不等待合并窗口。

当前实例自身有未处理候选时，编辑器等待恢复或丢弃后再允许输入，避免覆盖唯一副本；只有其他窗口/旧页面实例候选时，新输入仍持续保存到当前独立槽。恢复先写入自己的克隆，成功后才将源修订记为已处理；克隆失败仍可回填编辑器，但保留源修订可供下次发现，并提示手动保存或复制正文。

成功保存或编辑器内手动删除只清除当前页面实例拥有的副本；请求期间的新输入迁移到返回的 UUID/版本并继续保留。“忽略此恢复副本”仅在当前标签记录已处理的修订，不删除另一窗口的数据；`sessionStorage` 可用时同一修订刷新后不再提示，源窗口产生新修订时可再次发现。副本没有自动过期，退出或会话失效后保留供同账号重新登录恢复；它仅本机可用，不提供加密或跨设备同步。格式无效的恢复候选被跳过，不阻止当前窗口写副本；本机存储读写失败或配额耗尽会显示持续提示，不阻止手动编辑和保存。

“管理本机副本”列出当前账号各文章/页面的标题、时间、基线版本及估算占用，可查看纯文本并主动恢复；恢复仍保留源副本，旧服务器版本必须核对后提交。管理器的显式删除仅允许声明当前协调协议、且 Web Lock 确认没有编辑器使用的槽，确认期间内容更新则拒绝删除。升级前的 v1/v2、副本缺少协调声明或浏览器无锁 API 时，无法证明源窗口已关闭，所以保留查看/恢复；源窗口仍可删除自身副本，必要时可在浏览器站点存储中清除。安全清理能力不影响普通离线输入和本机恢复。

编辑器即时渲染在浏览器内完成，用于辅助写作；「发布效果预览」由用户主动触发，使用服务端与保存相同的 Markdown、清洗规则及当前插件配置，在隔离文档中展示正文。预览不持久化源文、HTML、引用或审计，不代表完整主题预览；正文在请求期间改变时拒绝展示旧结果。任务列表保存为不可交互的勾选框，启用或停用 Markdown 增强插件都保留任务状态。后台只在发布/预约前保存未提交输入；撤回与归档直接变更服务器状态并保留本地修改，避免撤回前先把未完成正文写入线上。版本冲突展示本地与服务器字段差异；显式覆盖绑定用户看到的服务器版本，期间再变更仍返回冲突。

后台的 Post/Page 管理 API 与 Post CLI 使用不可变 UUID 定位已有资源；当前没有 Page CLI，公开 URL 使用 slug。修改草稿 slug 不改变编辑身份；释放后的 slug 被新内容占用，也不会改变旧 ID 的目标。Post/Page 管理 API 统一使用 v1，不提供旧 slug 定位或兼容路由；分类、标签和系列仍通过 slug 管理。具体请求见[管理 API](admin-api.md)，决策见 [ADR-0014](adr/0014-content-commits-and-stable-admin-identity.md)。

## 2. 状态、可见性与删除

状态为 `draft`、`scheduled`、`published`、`archived`；可见性为 `public`、`private`，两者与 `deleted_at` 独立。

| 操作 | 结果 | 版本与公开效果 |
|---|---|---|
| 创建草稿 | `draft`，发布时间为空 | 初始版本 1，不公开 |
| 编辑 | 修改当前内容与关联 | 实际变化才递增版本；已发布的公开内容立即更新 |
| 立即发布 | `draft/scheduled → published` | 标题、正文不能空；无发布时间或时间仍在未来时改为当前时间，过去的发布时间保留 |
| 预约发布 | `draft/scheduled → scheduled` | 标题、正文不能空；时间必须在未来，写入 `published_at` 并锁定 slug |
| 到期发布 | `scheduled → published` | 保留预约时间；仅处理未删除且时间已到的记录 |
| 撤回 / 取消预约 | `published/scheduled → draft` | 保留发布时间及 slug 锁定，不再公开 |
| 归档 | 当前状态变为 `archived` | 不公开、不可编辑；可显式退回草稿后再编辑或发布 |
| 改为 private | 保持发布状态 | 退出匿名读取 |
| Post/Page 移入回收站 | 设置 `deleted_at`，保留原状态和关联 | 不再公开，仍占用 slug |
| Post/Page 恢复 | 清空 `deleted_at`，一律恢复为 `draft` | 不自动重新上线或重新预约，保留发布时间及 slug 锁定 |
| Post/Page 永久删除 | 仅允许删除回收站记录 | 清除媒体引用并释放 slug；文章同时删除标签/系列关联及整棵评论树 |

运行 `serve` 时启动预约任务，启动即检查，此后每 30 秒检查一次；停机期间到期的内容在下次运行时补发。`blog publish-due` 可手动处理全部已到期记录。任务通过行锁、`SKIP LOCKED` 和更新条件复核避免重复发布，不会重新发布已撤回、归档或删除的内容；成功发布递增内容版本，并同事务写入系统审计。

文章和页面匿名公开条件统一为 `published + public + deleted_at IS NULL + published_at <= 当前时间`。详情、列表、分类/标签/系列页、模板数据、RSS 与 sitemap 复用这些条件。private 不是“知道链接即可访问”，只能经授权的后台读取。当前没有整页缓存，撤回或删除后下一次公开请求即可反映变化。

文章作者由服务端身份确定，普通编辑不能转移作者。软删除用户会禁止其认证与后台操作，但不级联删除或自动撤回已有文章。公开作者资料使用白名单字段，不包含邮箱、口令、角色或 OAuth 数据。

## 3. 提交、版本与完整读取

创建和编辑通过领域聚合验证，包括标题/摘要长度、首次预约或发布后的 slug 锁定、已发布和已预约正文不得清空、系列权重为非负整数且系列 ID 不重复；应用层不能通过修改持久化快照绕过这些规则。

创建或替换文章系列关联时最多接受 100 个系列；应用先检查数量、重复 ID 和权重，再批量查询目录存在性。历史记录读取及保留系列集合的编辑不受该输入预算影响：省略字段或重发相同的系列 ID/权重集合均视为保留，数组顺序不影响判断，也不重复查询目录。

一次文章提交包含当前字段、标签集合、全部系列归属与权重、受影响系列版本、派生 HTML、媒体引用和审计。它们在同一数据库事务提交，失败整体回滚。页面采用相同的正文提交边界，不包含文章专属关系。

- 写入按资源 ID 和版本进行比较交换（CAS）。显式 `expected_version` 必须先匹配当前版本；未提供时仍以用例读到的版本提交，不能静默覆盖读后发生的并发修改。
- 内容编辑和状态命令无实际变化时不递增版本，但仍检查显式版本前提。删除也必须满足版本要求。
- 提交结果返回本次事务产生的完整记录和版本；后台文章详情一次读取正文、版本、标签和系列，避免拼接不同提交的数据。列表使用不携带完整正文的摘要查询，搜索可在数据库按源文匹配但不把正文带回列表；支持跨页搜索、分类及授权的作者范围筛选。
- 系列整体重排是独立批量操作：提交完整成员排列并检查系列版本，依次写入 `0..n-1` 权重；实际变化时递增系列版本及权重变化的成员文章版本。

Markdown 渲染与清洗在事务外的受限任务中完成，产物同时包含 `content_html` 和从该 HTML 提取的媒体 ID。仓储将源文、HTML、生成规则版本和引用集合一起提交；公开页面直接读取已保存的 HTML，不在阅读请求中重新转换 Markdown。

`content_render_version` 标识生成规则，规则升级通过重建派生物生效。重建按源文和业务版本做 CAS，同时刷新媒体引用，不改变编辑版本和业务更新时间。迁移与重建的执行边界见[当前数据库实现](database-current.md)。

## 4. 分类、标签与系列

| 类型 | 关系与读取规则 |
|---|---|
| 分类 | 文章至多一个分类；分类可有父级；目录默认只查询直接归属的文章 |
| 标签 | 文章与标签多对多，提交时去重；名称读取当前值 |
| 系列 | 文章与系列多对多；每个关联保存独立的非负整数 `position`，默认 0，可重复 |

分类、标签和系列的 slug 创建后不提供改名操作。名称更新影响所有引用它们的内容，不保留历史关联快照。删除标签或系列只移除关联，保留文章，并递增受影响文章版本以拒绝旧编辑副本覆盖；删除系列还清除其封面引用。分类仍受文章和子分类引用保护，须先显式调整关系。

标签、分类和系列更新在提交事务中返回本次记录和公开计数，系列另含按权限裁剪的总成员数，不在提交后重新读取目录。相同值仍检查版本，但不递增版本、更新时间或追加审计。

分类创建和移动在树锁内遍历完整祖先链，不按固定深度截断；访问过的节点去重，旧数据存在环时也能终止并拒绝接入。将分类移到根仍可用于修复已有环。

分类创建、移动和删除在统一树结构事务锁内检查祖先链，数据库自身的 CHECK 只能阻止直接自引用。

系列公开列表按 `position, post_id` 排序，过滤不可见文章，页面展示连续阅读序号。权重不代表章节编号，同一个系列内允许相同权重。草稿、私有和回收站文章保留关联。重排需 `series.manage`，并逐篇核验文章修改权限；成员读取也不能泄漏调用者无权阅读的草稿。

文章关系写入、系列变更和标签删除共用短事务 advisory lock，再取得实体行锁和校验版本，避免保存、删除和重排交叉加锁。只串行化这些写事务，不阻塞公开读取；正文渲染在取得事务锁之前完成。

## 5. 公开地址与 slug

文章地址为 `/posts/{slug}`，独立页面为 `/{slug}`；分类、标签、系列各有固定前缀。不同内容类型可以使用相同 slug。

- slug 创建时即非空且在各自表内唯一；未提供时应用生成临时值。
- 文章、页面首次预约或发布前允许修改 slug；产生 `published_at` 后永久锁定，取消预约、撤回或回收站恢复不会解锁。
- slug 只允许 Unicode 字母数字、`-`、`_`，上限 200 UTF-8 字节；不进行大小写折叠，禁止分隔符、空白、点和百分号。
- 撤回、归档、软删除保留 slug；物理删除释放它。当前没有旧路径重定向、别名、删除墓碑或任意嵌套路径。
- Page 不得占用系统根路径。保留名由[领域注册表](../crates/domain/src/content/page.rs)定义，按 ASCII 大小写不敏感比较，在创建、改名、发布和公开读取时检查；路由优先匹配固定系统入口。

RSS、sitemap 和 robots 不经过主题模板；收录范围与 URL 编码见[主题与渲染](themes-and-rendering.md)。

## 6. 媒体引用与独立公开链接

媒体引用覆盖 Post/Page 正文图片、Post/Series 封面、用户头像和站点 logo。文件使用随机 UUID 路径，展示文件名不参与寻址。格式依据图片头识别，支持 PNG、JPEG、GIF、WebP，不完整解码；上限为 10 MiB、单边 12,000 像素、总计 6,000 万像素。SVG、视频和任意附件不在范围内。

文件上传成功后，`/media/{id}` 立即可匿名读取，不要求站内引用，也不读取会话。文章改为 private、撤回、账号停用或图片进入回收站均不限制链接访问。文件字节固定，响应采用 `public, max-age=31536000, immutable` 和完整 SHA-256 ETag，支持条件 GET 与 HEAD。

站内使用位置以 `media_refs(media_id, source_type, source_id)` 为准，图片读取不依赖此表。正文引用来自最终清洗 HTML 的 `<img src="/media/{id}">`；Markdown 和保留的原始 HTML 图片计入，普通链接、代码块、注释和被清洗的标签不计入。同一来源正文和封面合并去重，与源文及 HTML 在同一事务同步。封面、头像有媒体外键；站点 logo 位于 settings.site JSONB，由同一引用事务校验。

新增引用要求媒体存在且未软删除，不按上传者限制。同一来源可以继续保留回收站图片，编辑正文或资料不会因历史图片卡住；解除后再次选择则算新引用。来源软删除保留引用，物理删除来源须同事务清除多态引用。

所有站内引用均计数，但使用位置只展示调用者可读或已公开的内容，差额通过 `hidden_references` 返回。Post/Page 的公开来源要求 published、public、未删除且发布时间已到。用户来源仅本人或具有 user.manage 的人可查看；图片公开不等于账号资料公开。零站内引用不代表无人使用，站外引用无法由此统计。

媒体库需要 media.read，上传需要 media.upload。软删除和恢复按本人 media.delete 或任意上传者 media.delete_any 授权；有引用也可软删除。头像由本人自助设置，递增 users.version 并保持 auth_version 和登录态；站点 logo 需要 settings.manage。

文章/页面编辑器的插图面板及封面选择器支持按文件名搜索与分页复用历史图片。翻页和搜索保留本地正文、光标与替代文字，插入仍需显式保存正文。正文框旁、插图上传和封面上传入口均说明：上传后图片链接立即公开，即使内容尚未发布或设为私密。

## 7. 上传、回收站与暂存清理

上传依次完成内容校验、写入暂存文件、原子移入正式目录，最后提交媒体行和审计。正式对象存在之前不登记可用记录。数据库与文件系统不是同一事务；登记失败时保留正式文件，因为提交可能成功但确认响应丢失。不会为了清理残留而删除可能已生效的图片。

媒体只有 deleted_at 软删除标记。回收站保留路径、原件和引用，恢复重新开放选择，ID 不复用。状态改变与审计在同一事务提交，失败整体回滚；版本过期返回冲突，即使请求目标状态相同也不绕过版本检查。

内容保存持有来源实体写锁，按媒体 ID 顺序取得 FOR SHARE；软删除取得同一媒体的 FOR UPDATE。引用先提交则软删除保留该引用；软删除先提交则拒绝新增引用，并回滚整次内容写入。数据库外键也阻止仍被引用的媒体行直接物理删除。

`blog media cleanup-staging` 仅清理一小时前的暂存残留，保留新暂存文件与所有正式对象。旧 media reclaim 已移除。正式媒体通过 `blog media purge plan/apply` 显式选择，维护窗口内复核回收站状态、版本、文件及已知引用；接受站外链接失效后，先事务提交删除与审计凭据，再删除文件。文件失败或提交结果丢失均用原计划重试。没有按零引用或软删除时间自动清理公开文件，未登记文件也不自动删除。

媒体管理及文章、系列、页面提交已通过新库定向验证。数据库和媒体原件仍须作为同一恢复单元，恢复工具当前限制见[运维与恢复](operations-and-recovery.md)。
