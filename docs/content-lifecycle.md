# 内容、路径与媒体生命周期

本文定义当前业务行为：单份正文、发布与删除、内容关系、公开地址和媒体来源。字段与数据库约束见[当前数据库实现](database-current.md)，权限见[身份与后台](identity-and-admin.md)，请求格式见[管理 API](admin-api.md)。

已采纳的新方案改为系列多对多、Post/Page 定时发布及回收站、归档可退草稿、预约即锁 slug，以及媒体链接独立公开、软删除保留文件。详细规则以[目标数据库设计](database-design.md)为准；媒体已适配新设计；内容与系列调整仍待实施，前五节保留旧内容行为说明。

## 1. 当前正文与资源身份

Post 和 Page 各保存一份 Markdown 源文。Post 有作者、摘要、分类、标签、系列和封面；Page 是无作者、无这些关联的独立页面。

保存已发布内容会直接更新线上，包括正文、标题、关联和可见性。当前没有编辑副本、修订历史、自动保存恢复点或逐篇撤销；需要保持修改私密时先撤回为草稿。草稿允许标题和正文为空，不代表已经提供自动保存。

后台的 Post/Page 管理 API 与 Post CLI 使用不可变 UUID 定位已有资源；当前没有 Page CLI，公开 URL 使用 slug。修改草稿 slug 不改变编辑身份；释放后的 slug 被新内容占用，也不会改变旧 ID 的目标。Post/Page 管理 API 统一使用 v1，不提供旧 slug 定位或兼容路由；分类、标签和系列仍通过 slug 管理。具体请求见[管理 API](admin-api.md)，决策见 [ADR-0014](adr/0014-content-commits-and-stable-admin-identity.md)。

## 2. 状态、可见性与删除

状态为 `draft`、`published`、`archived`；可见性为 `public`、`private`，两者独立。

| 操作 | 结果 | 版本与公开效果 |
|---|---|---|
| 创建草稿 | `draft`，首次发布时间为空 | 初始版本 1，不公开 |
| 编辑 | 修改当前内容与关联 | 实际变化才递增版本；已发布的公开内容立即更新 |
| 首次发布 | `draft → published`，记录 `published_at` | 标题、正文不能空；可见性为 public 时公开 |
| 撤回 | `published → draft` | 保留首次发布时间，不再公开 |
| 重新发布 | `draft → published` | 保留首次发布时间，按当前内容公开 |
| 改为 private | 保持发布状态 | 退出匿名读取 |
| 文章移入回收站 | 设置 `deleted_at`，保留原状态和关联 | 不再公开，仍占用 slug 与系列位置 |
| 文章恢复 | 清空 `deleted_at`；归档内容保持 archived，其余为 draft | 不自动重新上线 |
| 文章永久删除 | 仅允许删除回收站文章 | 删除标签、媒体引用并释放 slug 和系列位置 |
| 页面删除 | 物理删除，无回收站 | 删除媒体引用并释放 slug，不可恢复 |

`archived` 是不可编辑、不可重新发布的终态。当前没有归档操作入口；状态与 `page.archive` 权限注册项不等于已经交付归档流程。

文章匿名公开条件为 `published + public + deleted_at IS NULL`；页面为 `published + public`。详情、列表、分类/标签/系列页、模板数据、RSS 与 sitemap 复用这些条件。private 不是“知道链接即可访问”，只能经授权的后台读取。当前没有整页缓存，撤回或删除后下一次公开请求即可反映变化。

文章作者由服务端身份确定，普通编辑不能转移作者。软删除用户会禁止其认证与后台操作，但不级联删除或自动撤回已有文章。公开作者资料使用白名单字段，不包含邮箱、口令、角色或 OAuth 数据。

## 3. 提交、版本与完整读取

创建和编辑通过领域聚合验证，包括标题/摘要长度、首次发布后的 slug 锁定、已发布正文不得清空、系列位置为正整数；应用层不能通过修改持久化快照绕过这些规则。

一次文章提交包含当前字段、标签集合、系列归属与位置、受影响系列版本、派生 HTML 和媒体引用。它们在同一数据库事务提交，失败整体回滚。页面采用相同的正文提交边界，不包含文章专属关系。

- 写入按资源 ID 和版本进行比较交换（CAS）。显式 `expected_version` 必须先匹配当前版本；未提供时仍以用例读到的版本提交，不能静默覆盖读后发生的并发修改。
- 内容编辑和状态命令无实际变化时不递增版本，但仍检查显式版本前提。删除也必须满足版本要求。
- 提交结果返回本次事务产生的完整记录和版本；后台文章详情一次读取正文、版本和标签，避免拼接不同提交的数据。列表使用不携带完整正文的摘要查询。
- 系列整体重排是独立批量操作：提交完整成员排列并检查系列版本，递增系列和成员文章版本。

Markdown 渲染与清洗在事务外的受限任务中完成，产物同时包含 `content_html` 和从该 HTML 提取的媒体 ID。仓储将源文、HTML、生成规则版本和引用集合一起提交；公开页面直接读取已保存的 HTML，不在阅读请求中重新转换 Markdown。

`content_render_version` 标识生成规则，规则升级通过重建派生物生效。重建按源文和业务版本做 CAS，同时刷新媒体引用，不改变编辑版本和业务更新时间。迁移与重建的执行边界见[当前数据库实现](database-current.md)。

## 4. 分类、标签与系列

| 类型 | 关系与读取规则 |
|---|---|
| 分类 | 文章至多一个分类；分类可有父级；目录默认只查询直接归属的文章 |
| 标签 | 文章与标签多对多，提交时去重；名称读取当前值 |
| 系列 | 文章至多一个系列；系列 ID 和正整数位置同时设置或清空 |

分类、标签和系列的 slug 创建后不提供改名操作。名称更新影响所有引用它们的内容，不保留历史关联快照。被文章引用的目录项不能删除；有子分类的分类也不能删除，须先显式调整关系。

分类创建、移动和删除在统一树结构事务锁内检查祖先链，数据库自身的 CHECK 只能阻止直接自引用。

系列位置在系列内唯一，允许空档；草稿、私有和回收站文章仍占位置。公开列表按存储位置排序并过滤不可见文章，展示连续阅读序号，不暴露内部空档。重排需 `series.manage`，并逐篇核验文章修改权限；成员读取也不能泄漏调用者无权阅读的草稿。存储先按固定 ID 顺序锁系列，再锁文章，交换位置时延后唯一约束检查，提交时恢复唯一。

## 5. 公开地址与 slug

文章地址为 `/posts/{slug}`，独立页面为 `/{slug}`；分类、标签、系列各有固定前缀。不同内容类型可以使用相同 slug。

- slug 创建时即非空且在各自表内唯一；未提供时应用生成临时值。
- 文章、页面首次发布前允许修改 slug；产生 `published_at` 后永久锁定，撤回或回收站恢复不会解锁。
- slug 只允许 Unicode 字母数字、`-`、`_`，上限 200 UTF-8 字节；不进行大小写折叠，禁止分隔符、空白、点和百分号。
- 撤回、归档、软删除保留 slug；物理删除释放它。当前没有旧路径重定向、别名、删除墓碑或任意嵌套路径。
- Page 不得占用系统根路径。保留名由[领域注册表](../crates/domain/src/content/page.rs)定义，按 ASCII 大小写不敏感比较，在创建、改名、发布和公开读取时检查；路由优先匹配固定系统入口。

RSS、sitemap 和 robots 不经过主题模板；收录范围与 URL 编码见[主题与渲染](themes-and-rendering.md)。

## 6. 媒体引用与独立公开链接

媒体引用覆盖 Post/Page 正文图片、Post/Series 封面、用户头像和站点 logo。文件使用随机 UUID 路径，展示文件名不参与寻址。格式依据图片头识别，支持 PNG、JPEG、GIF、WebP，不完整解码；上限为 10 MiB、单边 12,000 像素、总计 6,000 万像素。SVG、视频和任意附件不在范围内。

文件上传成功后，`/media/{id}` 立即可匿名读取，不要求站内引用，也不读取会话。文章改为 private、撤回、账号停用或图片进入回收站均不限制链接访问。文件字节固定，响应采用 `public, max-age=31536000, immutable` 和完整 SHA-256 ETag，支持条件 GET 与 HEAD。

站内使用位置以 `media_refs(media_id, source_type, source_id)` 为准，图片读取不依赖此表。正文引用来自最终清洗 HTML 的 `<img src="/media/{id}">`；Markdown 和保留的原始 HTML 图片计入，普通链接、代码块、注释和被清洗的标签不计入。同一来源正文和封面合并去重，与源文及 HTML 在同一事务同步。封面、头像有媒体外键；站点 logo 位于 settings.site JSONB，由同一引用事务校验。

新增引用要求媒体存在且未软删除，不按上传者限制。同一来源可以继续保留回收站图片，编辑正文或资料不会因历史图片卡住；解除后再次选择则算新引用。来源软删除保留引用，物理删除来源须同事务清除多态引用。

所有站内引用均计数，但使用位置只展示调用者可读或已公开的内容，差额通过 `hidden_references` 返回。Post/Page 的公开来源要求 published、public、未删除且发布时间已到。用户来源仅本人或具有 user.manage 的人可查看；图片公开不等于账号资料公开。零站内引用不代表无人使用，站外引用无法由此统计。

媒体库需要 media.read，上传需要 media.upload。软删除和恢复按本人 media.delete 或任意上传者 media.delete_any 授权；有引用也可软删除。头像由本人自助设置，递增 users.version 并保持 auth_version 和登录态；站点 logo 需要 settings.manage。

## 7. 上传、回收站与暂存清理

上传依次完成内容校验、写入暂存文件、原子移入正式目录，最后提交媒体行和审计。正式对象存在之前不登记可用记录。数据库与文件系统不是同一事务；登记失败时保留正式文件，因为提交可能成功但确认响应丢失。不会为了清理残留而删除可能已生效的图片。

媒体只有 deleted_at 软删除标记。回收站保留路径、原件和引用，恢复重新开放选择，ID 不复用。状态改变与审计在同一事务提交，失败整体回滚；版本过期返回冲突，即使请求目标状态相同也不绕过版本检查。

内容保存持有来源实体写锁，按媒体 ID 顺序取得 FOR SHARE；软删除取得同一媒体的 FOR UPDATE。引用先提交则软删除保留该引用；软删除先提交则拒绝新增引用，并回滚整次内容写入。数据库外键也阻止仍被引用的媒体行直接物理删除。

`blog media cleanup-staging` 仅清理一小时前的暂存残留，保留新暂存文件与所有正式对象。旧 media reclaim 已移除。没有按零引用或软删除时间自动清理公开文件；独立物理清理入口、保留期及媒体完整恢复仍属于收尾批次。

媒体管理已经通过新库定向验证，但完整文章、系列与页面生命周期还需后续批次适配。数据库和媒体原件仍须作为同一恢复单元，恢复工具当前限制见[运维与恢复](operations-and-recovery.md)。
