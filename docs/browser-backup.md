# 后台备份与恢复

入口为后台“系统 → 备份与恢复”，也可直接访问 `/recovery`。统一 Docker 镜像默认启用此功能。恢复页面由独立于业务数据库的监听层提供，数据库故障和恢复期间仍可打开。

## 第一次使用

1. 使用受保护的 `admin` 角色账号与本地密码验证身份。只有普通管理权限的自定义角色不能取得恢复权限；仅使用 OAuth 的管理员可先在账号中配置本地密码。
2. 点击“生成并下载恢复密钥”，将文件保存在电脑或密码管理器中。
3. 重新选择下载的文件，确认已保存。确认之前不会创建自动备份。
4. 点击“立即备份”，完成后在列表中下载加密副本。备份与密钥应分别保存在服务器之外。

密钥只在生成时交付，服务器保存公钥和应急验证摘要。下载中断、尚未确认保存时，可以重新生成。确认后请使用已经保存的密钥。

## 自动备份与远程存储

可选择每日或每周运行、UTC 时间及本地/远程保留数量；页面同时显示本地时间格式的下一次运行时间。恢复前自动生成的回滚副本不受本地自动保留清理影响，可在任务完成后手动删除。

远程存储支持兼容 S3 的服务。填写服务地址、区域、存储桶、本站专用路径和访问密钥，点击“测试连接并保存”。测试会创建一个随机小对象，核对读取及列表权限后删除。已有访问密钥留空表示保留。远程列表支持取回副本后恢复。

每个部署使用不同远程路径。保留清理在成功上传后执行，只处理指定路径中的博客备份。远程失败时保留本地副本和旧副本，在任务记录中显示警告，可点击“重传远程”。远程上传期间站点已经重新开放访问。

## 原地恢复

1. 在列表选择副本，上传一个 `.tar.gz.age` 文件，或从远程存储取回。上传上限为 2 GiB，实际容量还受临时空间与磁盘容量限制。暂存文件可直接在页面删除。
2. 选择该副本对应的恢复密钥，点击“验证备份”。完整解密后检查备份格式、迁移版本、清单与文件校验和、媒体、配置和可用空间。
3. 核对备份时间，输入“恢复此站点”，开始恢复。会先生成恢复前加密副本，使用本次选择的密钥加密。
4. 完成后用备份中的管理员账号重新登录。旧业务会话和邮件账号链接全部失效。

默认情况下，恢复前副本创建失败会终止操作，原数据尚未改动。空站点或数据库损坏时，可明确勾选“无法创建恢复前副本时，仍继续恢复”；此时可能没有自动回滚副本。

恢复覆盖业务数据库、媒体、主题及邮件配置。当前域名、端口、反向代理、数据库连接和挂载路径由当前部署管理；备份策略、远程存储凭据和恢复任务记录也保留在当前部署。显式部署环境变量继续优先于恢复的邮件/OAuth 密钥。

## 中断与应急恢复

关闭浏览器不会取消任务。恢复发生数据写入前，会在数据库外持久记录维护状态。进程在恢复中途退出后，重启仍保持维护状态；使用已保存的恢复密钥登录 `/recovery`，重试恢复或选择任务中的恢复前副本回滚。校验未完成时不能强行重新开放站点。

数据恢复已完成、仅站点重新加载失败时，修复原因后点击“重新启动站点”。普通数据库停机也可在数据库服务恢复后通过此按钮重新连接。

新服务器先按 [1Panel 部署](1panel.md)启动空站点，从安装页进入恢复，用本次部署的安装码授权。第一次恢复会在修改数据前关联导入的恢复密钥；即使这次恢复中断，也能用此密钥进入应急页面。

## 适用边界

- 当前采用单站点、单应用实例。备份期间暂停站点请求并排空业务任务，生成一致副本后重新开放；检测到外部数据库连接时拒绝备份或恢复。不能同时运行旧的外部备份/维护调度和后台恢复操作。
- 默认数据库结构所有者账号可原地恢复。分离权限的受限运行账号没有恢复建表权限，需要部署方使用对应的高级恢复流程；页面不会自动提升数据库权限。
- 接受格式 `2` 且当前已知 schema id、迁移编号及校验和一致的备份，兼容同一数据库结构下的不同镜像构建。其他迁移版本会在覆盖数据前拒绝；旧基线转换仍需专门迁移。
- 每个上传最多 2 GiB，解压总量最多 4 GiB、10 万项。默认临时存储为容器 tmpfs，可调整编排的 `tmpfs` 大小；旧编排使用 `BLOG_BACKUP_TMPFS_SIZE`。明文仅在私有临时目录暂存，备份目录保存加密文件。
- 控制器数据位于配置卷的 `recovery/`，含独立任务记录、策略和加密副本。业务备份不会递归备份这个目录。恢复管理会话重启失效；敏感操作授权 15 分钟，进度查看最多 1 小时，期间可以重新验证身份。
- 发布镜像中的恢复工具默认启用。源码开发可安装 Python、age、PostgreSQL 客户端及可选 boto3 后设置 `BLOG_BROWSER_RECOVERY=1`；`BLOG_BACKUP_DIR` 指定独立状态目录。旧脚本入口见 [Compose 备份恢复](compose-backup.md)。

实现选择见 [ADR-0021](adr/0021-browser-backup-and-in-place-recovery.md)。本地可重复验收入口为 `scripts/test_browser_compose.py`；真实存储服务的权限、成本、容量和恢复时间需要在目标部署验证。
