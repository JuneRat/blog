所有 8 次成功握手均记录 `TLSv1.3`；STARTTLS 的恢复前后各记录 2 次升级及加密后的 EHLO。没有明文 AUTH 或邮件传输。每次邮件流程均检查应用原始日志，未出现测试收件地址、凭据、AUTH 编码或重置 token。

测试 SMTP 仅绑定应用容器的回环地址，使用临时 CA。私钥与认证设置通过私有管道送入非 root 收件容器，容器禁用日志，密钥文件位于 tmpfs；宿主临时证书目录随测试结束删除。邮件只在内存中保留，通过私有管道消费 token，不转发外部地址。

恢复站点使用新的测试端口，但邮件仍应指向备份中的公开站点地址。脚本单独校验此地址，再在恢复站点提交收到的 token，避免把“恢复端口不同”误判成链接配置丢失。生产恢复仍需单独切换反向代理／域名。

`recovery_check.media=0` 是隔离 HTTP check 对“未软删除媒体”的计数；该测试刻意保留被正文和历史引用的软删除媒体，另有媒体原件字节比较和引用保护核验。

## 复现与剩余边界

在上述两个本地镜像仍可用、主机有 Python 3 和 OpenSSL 时，使用该工具提交运行：

```sh
BLOG_EXPECT_REVISION=e610be9625a276b11885ea73b4e202de5b9d575c \
  python3 -B scripts/test_compose.py \
  --image codex-blog-release:e610be9625a2 \
  --ops-image codex-blog-release:e610be9625a2-ops \
  --smtp-security starttls --report /tmp/compose-starttls-new-run.json

BLOG_EXPECT_REVISION=e610be9625a276b11885ea73b4e202de5b9d575c \
  python3 -B scripts/test_compose.py \
  --image codex-blog-release:e610be9625a2 \
  --ops-image codex-blog-release:e610be9625a2-ops \
  --smtp-security tls --report /tmp/compose-tls-new-run.json

python3 -B scripts/test_release_upgrade.py \
  --from-image codex-blog-task-health:9057c1c \
  --image codex-blog-release:e610be9625a2 \
  --report /tmp/upgrade-new-run.json
```

本轮补齐了此前[原生 SMTP 验收](smtp-tls-2026-10-03.md)未覆盖的新镜像部署恢复和成功 TLS 1.3 握手。证书拒绝、认证错误、SMTP 拒收及投递期限仍引用原生 15 场景证据，没有在本轮容器里重复故障矩阵。

这仍是本地 Linux arm64 证据。外部 SMTP 供应商、真实邮箱收件和垃圾邮件处理、目标环境域名与网络、amd64 运行、生产资源限制、容量及 RPO/RTO 按[路线图 M5](../product-roadmap.md#3-里程碑与验收入口)单独验收。没有据此勾选生产上线门槛。
