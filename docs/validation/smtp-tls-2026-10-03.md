# 2026-10-03 本地 SMTP 加密、认证与故障验收

**15 个场景全部通过**，总耗时 198.041 秒。隐式 TLS 与 STARTTLS 各完成邀请和找回邮件投递，共接收 4 封；13 个失败场景均验证邀请与异步找回，共撤销 26 个失败链接。收到正文后未确认、分阶段缓慢响应的投递分别在 12.014 / 12.013 秒结束，符合 12 秒总期限及测试容差。

## 协议与业务结果

| 场景 | 数量 | 实际观察与断言 |
|---|---:|---|
| TLS / STARTTLS 成功 | 2 | 每种模式 2 次 TLS 握手、加密后的 EHLO 和成功认证，接收 2 封邮件；STARTTLS 另记录 2 次升级。邀请首次设密、一次性链接重放拒绝、限流、找回响应不枚举账号、旧会话撤销及撤权后拒绝写入均通过 |
| 证书拒绝 | 5 | 两种模式拒绝未知 CA、主机名不符；隐式 TLS 另拒绝过期证书。邀请和找回均未发送 AUTH 或正文 |
| 认证失败 | 2 | 两种模式各记录 2 次真实握手与认证拒绝，未发送正文 |
| STARTTLS 缺失／拒绝 | 2 | 各完成 2 次明文 EHLO；拒绝升级场景另有 2 次 STARTTLS 命令。对端即使在明文连接宣告 AUTH，应用也未发送凭据或邮件 |
| 收件人拒绝 | 1 | 2 次加密认证成功，2 次 RCPT 拒绝，无 DATA 正文 |
| 正文拒绝 | 1 | 收到 2 份正文后返回 SMTP 554，未确认接收；已收到的邀请 token 通过真实重置接口验证为无效 |
| 正文确认超时 | 1 | 收到 2 份正文后不返回确认；邀请在 12.014 秒失败，实际收到的邀请 token 被重置接口拒绝 |
| 总投递期限 | 1 | 每次服务端响应延迟 4 秒，单阶段未达到 10 秒配置期限；累计投递在 12.013 秒结束，未完成认证或接收邮件 |

每个失败场景都验证以下行为：

- 管理员邀请返回通用 `500 internal_error`，未暴露 SMTP 原始错误、认证信息或收件地址。
- 自助找回立即返回 `202`，响应与不存在邮箱相同；本轮记录耗时为 0–1 ms（毫秒取整），应用随后在后台撤销失败链接。
- 邀请与找回的持久化链接均满足 `expires_at = issued_at`，26 个链接全部失效；原密码与管理员会话仍可用。
- 邮件只留在有容量和大小限制的内存收件器中。检查应用日志未出现测试凭据、AUTH 编码、收件地址、重置 token 或私有 SMTP 响应标记。

超时结果包含 HTTP 与本机调度开销；它们验证期限行为，不是外部邮件服务的延迟承诺。DATA 超时本轮由约 12 秒的总期限结束，未据此认定 10 秒传输层超时先触发。

## 复现与剩余边界

按[本地验收说明](../acceptance.md#本地-smtp-加密与故障验收)准备专用回环 PostgreSQL、构建后台，并设置 `BLOG_TEST_ADMIN_URL`、`BLOG_TEST_PG_CONTAINER`。在要验证的源码树构建并注入该提交的完整标识：

```sh
app_revision="$(git rev-parse HEAD)"
BLOG_BUILD_REVISION="$app_revision" cargo build --offline --release -p server --bin blog
python3 -B scripts/acceptance_smtp_tls.py \
  --binary target/release/blog \
  --expected-revision "$app_revision" \
  --report /tmp/blog-smtp-tls-new-run.json
```

报告路径须不存在；可重复指定 `--case` 定向执行。原始证据对应上表的应用提交与工具哈希，后续提交的复验应保存新报告。

本轮使用新增 CA 配置后的原生 release 构建；此前 `9fb6c24` Docker 镜像的部署、恢复和容量结果仍保留各自构建身份。后续[固定 Docker 镜像验收](release-mail-2026-10-03.md)已用 `e610be9` 补齐两种加密模式、特殊字符凭据与多行 CA 的实际备份恢复，以及恢复开放后的邀请和找回投递。

本轮仅协商 TLS 1.2；成功 TLS 1.3 握手另见上述容器记录。外部供应商认证与发件域名、真实邮箱收件及垃圾邮件处理仍未验证。生产域名、资源限制、告警与恢复目标继续按[路线图 M5](../product-roadmap.md#3-里程碑与验收入口)确认。
