# 在 1Panel 中部署

日常安装、备份和恢复都可以通过网页完成。部署使用一个博客镜像；编排会自动拉取官方 PostgreSQL 镜像，生成数据库密码并准备持久存储。博客镜像包含网站、后台、迁移和备份恢复工具。

## 获取部署模板

先将项目推送到自己的 GitHub 仓库，运行 `container` Actions 的手动发布，或推送 `v*` 标签。构建及隔离验收通过后，下载 `blog-compose-registry-linux-amd64-<commit>` 配置包。具体发布和私有仓库配置见 [镜像发布](docker-compose.md#从-ghcr-拉取镜像并部署到-1panel)。

配置包中的 `ops/1panel/compose.yaml` 已固定本次通过验收的博客镜像地址。源码中的[编排模板](../ops/1panel/compose.yaml)也可使用，需自行填写 `BLOG_IMAGE`。当前正式流水线发布 Linux amd64 镜像。

## 创建编排

在 1Panel 的“容器 → 编排”中创建编排，使用编辑器粘贴模板内容，或通过面板文件管理上传模板后选择路径。1Panel 支持编辑器、文件路径和编排模板这三种创建方式。[1Panel 编排说明](https://1panel.pro/docs/v2/user_manual/containers/composes/)

参照模板旁的 `.env.example` 设置变量：

| 变量 | 填写内容 |
|---|---|
| `BLOG_IMAGE` | 源码模板需填写镜像地址；发布配置包已在编排中固定镜像，可省略 |
| `BLOG_PUBLIC_BASE_URL` | 实际访问地址，例如 `https://blog.example.com` |
| `BLOG_INSTALL_TOKEN` | 自己保存的安装码，至少 20 个字符；安装时需要输入 |
| `BLOG_HTTP_PORT` | 默认 `8080`；同一服务器部署多个站点时分别选择未占用端口 |

可以通过面板文件管理把变量保存为与模板同目录的 `.env`，设为仅所有者读写。创建并启动编排即可，不需要填写数据库地址或创建数据库账号。数据库密码由一次性初始化服务生成并保存在私有数据卷中；初始化服务退出成功属于正常状态。安装完成前，博客容器的就绪检查会显示未就绪。

每个站点使用独立编排名和数据卷。更换编排名会建立另一组卷，不能用它代替升级。

## 配置域名并安装

将域名解析到服务器，在 1Panel 的“网站”中创建反向代理网站，绑定域名并启用 HTTPS。[1Panel 创建网站说明](https://1panel.pro/docs/v2/user_manual/websites/website_create/)

OpenResty 使用宿主机网络时，代理目标填 `http://127.0.0.1:8080`，端口与上一步一致。使用独立容器网络的代理，需要先连通受控内部网络。博客的端口默认只绑定宿主机回环地址。反向代理请求体上限至少设为 4 MiB；大备份在网页中分块上传，每块最多 4 MiB。

打开 `https://你的域名/install`，输入设置的安装码，创建管理员。数据库信息和域名已由编排提供。已有备份时，点击“从备份恢复站点”，使用安装码进入恢复页面，上传备份和恢复密钥即可。

## 日常操作与更新

从后台“系统 → 备份与恢复”下载并确认恢复密钥，再开启自动备份、配置远程存储。操作步骤见[后台备份与恢复](browser-backup.md)。

更新前在后台创建备份并下载到电脑。取得新版本的已验收镜像地址，在原编排中更新博客与初始化服务的镜像引用，然后通过 1Panel 拉取并重新创建服务。保留编排名、数据卷、域名和安装码配置。启动会执行支持的数据库迁移；需要恢复时，使用与备份迁移版本兼容的镜像。回退镜像本身不会回退数据库。
