# ADR-0005：跨资源一致备份与隔离恢复

- 状态：提议
- 记录日期：2026-09-21
- 关联决策：[ADR-0010：持久会话与恢复失效](0010-persistent-postgres-sessions.md)
- 当前参考：[备份与恢复](../operations-and-recovery.md)、[扩展设计候选](../extensions-and-data.md)

## 背景

数据库事务不能覆盖对象存储和第三方服务。独立导出数据库、复制媒体或恢复投递记录，可能产生缺失附件、无法解密的配置和重复外部投递，需要统一恢复边界。

## 决策

提议先采用维护窗口：停止全部写入与相关 worker，在静止状态下建立数据库、媒体、主题及秘密恢复材料的关联清单，验证后才标记备份完成。

恢复先隔离，再使旧会话和待用凭据失效，并重建必要的派生数据。若已启用外部投递，核对远端结果后再开放。未来改用在线方案时另记替代决策，并验证等价的跨资源恢复语义。

## 考虑过的方案

在线数据库快照配合对象版本、增量日志或持续恢复，可以减少停机和数据丢失窗口，但需要更复杂的一致性切点、对象保留与重放协议，初期不默认承担这些成本。单独逻辑导出不能替代完整部署备份。

## 后果与限制

维护窗口需要暂停服务写入，并准备备份容量、独立密钥保管和定期演练。备份频率、保留期及 RPO/RTO 由部署规格确定，本决策没有数值承诺。

恢复数据库不能撤销第三方副作用，也不能保证恰好一次重放。秘密材料、有效引用对象和外部在途请求各有核验责任，不能仅凭数据库导入成功开放服务。

## 后续变更

维护备份与隔离恢复脚本，以及核心数据的本机往返演练，已落实部分方案。工具需显式附加媒体目录，且不提供完整媒体引用与原件一致性核验；工具检查通过不等于完整恢复或生产验收通过。

完整媒体恢复、部署层停止写入编排与 RPO/RTO 仍待验收，本 ADR 保留提议状态。实际命令、工具限制和已有证据由备份与恢复文档维护，不在此复制操作手册。
