# ADR-0002：MiniJinja 与受控模板数据函数

- 状态：已采纳
- 记录日期：原记录未注明
- 关联决策：[ADR-0004：公开缓存提议](0004-public-cache-generation.md)、[ADR-0015：集中渲染](0015-rendered-content-runtime-and-module-boundaries.md)
- 当前参考：[主题与渲染](../themes-and-rendering.md)、[桥接原型报告](../../spikes/template-bridge/README.md)

## 背景

主题需要通过宿主函数获取受限的公开数据，而同步模板引擎与异步数据库之间存在执行、预算和请求隔离问题。

## 决策

采用 MiniJinja，替代最初的 Tera 计划。选择依据是其函数、参数和状态扩展模型，不以“Tera 不支持函数”或未经测量的性能优势作为理由。

保留两条取数路径：常用数据异步预取，模板函数未命中请求级缓存时执行受控查询。函数只能访问宿主提供的公开数据契约，错误作为受控失败返回，不无限排队或静默降级。

## 考虑过的方案

清单声明预取作为对照方案，可以简化渲染期间的 I/O，但会限制动态查询或增加声明语言的设计成本。它仍需处理数据失效及 CPU、输出预算，不能代替这些约束。

## 后果与限制

正式冻结主题函数契约前，需要验证慢查询、取消、并发上限和上下文隔离。该验证不阻塞仅依赖预取的内容闭环；若桥接不成立，应调整桥接或 API，而不是取消函数取数能力。

桥接在阻塞任务中使用当前 Tokio runtime 驱动带剩余截止时间的异步查询，不在异步执行线程内阻塞，也不为每次渲染新建 runtime。请求级上下文、查询/调用预算、fuel、递归及输出限制共同约束执行。fuel 不覆盖宿主 I/O，取消调用者也不能提前释放仍在执行的任务许可。

请求级查询缓存不等于跨请求页面缓存；后者的新鲜度与撤回语义仍需按 [ADR-0004](0004-public-cache-generation.md)单独验证。

## 后续变更

2026-09 的独立原型结论为**桥接方案可行**，采纳预算化函数取数与预取优先的组合。测量环境、测试矩阵、吞吐和开销数据保留在[原型报告](../../spikes/template-bridge/README.md)，生产 crate 不依赖该实验工程。

受控模板函数已进入生产代码；[ADR-0015](0015-rendered-content-runtime-and-module-boundaries.md)进一步把执行调度集中到基础设施渲染运行时。当前函数契约和预算参数由主题文档维护。
