# ADR-0021：统一镜像、网页备份与原地恢复

- 状态：已采纳
- 日期：2026-10-04
- 当前参考：[后台备份恢复](../browser-backup.md)、[1Panel 部署](../1panel.md)
- 关联：补充 0005 的一致性要求与 0020 的任务边界；替代“恢复仅支持独立部署”的产品入口限制。

## 背景

面向非技术用户的单机博客，需要在面板拉取一个博客镜像，并通过网页完成备份、计划、远程存储和恢复。恢复正在使用的数据库时，依赖该数据库的登录、任务表和页面无法作为唯一控制入口。

## 决策

应用、PostgreSQL 客户端、加密及恢复工具放在一个博客镜像中。数据库由用户准备，可以使用已有实例，也可以写在同一 Compose 中。用户选择完整的单文件示例，将发布的博客镜像地址写入 `image`，启动时自动拉取。安装向导先只读检查连接、空库与权限，确认安装时才保存私有配置并执行迁移。HTTP 服务以非 root 用户运行，不挂载 Docker socket。

2026-10-04 的部署简化取消了一次性初始化服务、自动写入博客数据库配置及面向用户的配置包。发布保留已测试镜像的身份校验，结果页直接显示镜像地址；CI 内部镜像传递不属于用户部署步骤。

`application::backup` 定义恢复控制端口，`interfaces::http_backup` 提供嵌入页面、Cookie/CSRF 和分块上传下载。服务装配层拥有动态业务路由、请求排空、任务停止和重建生命周期。独立 Python worker 通过私有 stdin 接收参数，执行数据库/归档/S3 操作并维护本地原子任务日志。

持有受保护 `admin` 角色的管理员重新验证本地密码后获得短期恢复能力；既有角色、认证版本在业务运行期间继续复核。应急凭据由恢复密钥派生摘要，管理会话保存在进程内。状态目录、恢复阻断标记和策略位于数据库外的配置卷；恢复不依赖业务任务表，也不迁移控制器目录。新部署的首次恢复必须先提供本部署的安装码。

备份排空站点请求、停止后台写入并关闭连接池，再生成数据库、媒体和主题的一致加密副本。随后重建站点并开放访问，远程上传与保留清理在开放之后执行。外部数据库连接存在时拒绝操作。

恢复先验证格式、已知迁移校验和、文件、配置和空间；生成加密回滚副本后，持久化恢复阻断标记。数据库恢复使用单事务，媒体和主题在业务访问被阻断期间替换并同步到磁盘。恢复后撤销会话和一次性账号链接，再重建站点，成功后清除阻断标记。重启看到阻断标记时只开放恢复入口，不能跳过未完成校验强行开放业务。

## 代价与边界

备份会短暂停止站点访问；该版本针对单实例。数据库与文件不能构成同一个原子事务，持久标记、加密回滚副本和幂等重试承担中断恢复职责。明确授权跳过恢复前副本仅适用于原数据已损坏或空站点，不提供自动回滚保证。

兼容性根据备份格式和迁移校验和判定，取消网页恢复对同一二进制哈希的依赖。当前支持相同已知迁移集合；跨迁移版本需要后续显式兼容实现。旧独立恢复脚本保留自己的严格构建身份约束和高级运维入口。

## 验证

隔离容器验收覆盖管理员与普通账号权限、CSRF、密钥确认、加密与损坏归档、原地恢复、旧会话撤销、恢复中断后的阻断与回滚、S3 协议往返及故障、新部署恢复，以及数据库不可用时的应急入口。实际浏览器验证密钥下载、文件选择、创建和验证备份，以及移动视口。执行记录见[本地验收](../validation/browser-recovery-2026-10-04.md)。
