# ADR-0018：有界 HTML 维护与只读预检

- 状态：已采纳
- 记录日期：2026-09-28
- 关联决策：细化 [ADR-0017](0017-explicit-html-rebuild.md) 的显式重建执行控制，不改变保存时渲染与逐记录事务原则
- 当前参考：[架构](../architecture.md)、[运维](../operations-and-recovery.md#html-显式重建)

## 背景

显式重建已与启动分离，但命令仍持续执行到全库处理完毕，缺少预计工作量和单次上限。失败发生在批次中间时，原接口不能返回此前已提交数量，错误也缺少记录定位；从头查询旧版本记录还会重复扫描已处理区域。

## 决策

应用层定义 `HtmlRebuildStore` 和维护用例，负责参数校验、文章/页面/评论共用的批次额度、游标推进及部分完成结果。基础设施端口按 UUID 升序查询限定数量的 ID，再逐条读取源文，内存仅持有一篇正文及其渲染结果，不随批次正文总量增长。以源文和编辑版本 CAS 逐条提交；HTML、媒体引用和审计仍同事务。候选记录已删除或已更新为当前渲染版本时跳过；游标跨过本轮已检查的冲突记录，下一轮再从剩余旧版本记录开始。

只读预检独立校验已应用的迁移，再用单条查询统计三类数量，不渲染、不写入、不初始化结构或权限。它与受限运行账号的迁移校验共用迁移锁及校验和检查，不调用可能建表的 SQLx 迁移入口。

接口层输出结构化计数、剩余数量及 `has_more`。记录级失败包含类型和 UUID，并保留此前确认提交的计数；失败返回非零退出码，不把旧统计当成当前剩余数量。部署入口仅保留依赖装配、结构准备与恢复隔离。

## 后果与限制

运维可以先预估、再分次重建，并定位失败记录。正常退出只表示本轮没有错误，部署流程须检查剩余标志以确认全量完成。并发冲突留待后续重跑，不强行覆盖。

每次统计和批次查询使用各自快照，批次上限限制检查记录数，不是数据库扫描时间或渲染耗时上限。提交确认丢失时只能报告已确认部分，重跑依赖持久化渲染版本判定实际进度。本次不引入持久任务队列或跨请求全站快照。

验证包括 PostgreSQL 强制只读预检、空库不初始化、跨来源额度、游标越过并发冲突、部分提交后的失败重试，以及既有 HTML/引用/审计回滚。
