# ADR-0017：HTML 重建改为显式维护

- 状态：已采纳
- 记录日期：2026-09-28
- 关联决策：局部替代 [ADR-0015](0015-rendered-content-runtime-and-module-boundaries.md) 中启动、内容命令与完整迁移自动重建派生物的选择；覆盖 [ADR-0016](0016-confirmed-blog-schema.md) 扩展的评论 HTML
- 当前参考：[架构](../architecture.md)、[主题与渲染](../themes-and-rendering.md)、[运维](../operations-and-recovery.md#html-显式重建)

## 背景

原完整迁移入口依次执行结构迁移、文章/页面重建和评论重建。网站启动、文章 CLI 和到期发布都会调用它，启动耗时随旧版本内容量增长；历史正文中的无效媒体引用或渲染失败会阻止无关命令和服务启动。

## 决策

普通启动及业务命令仅执行或校验数据库结构。删除组合式基础设施 `migrate` 函数，保留独立的 `migrate_schema`；`migrate` CLI 同样只负责结构。

新增 `rebuild-html` 受控 CLI，先确保结构就绪，再显式重建文章、页面及评论的旧版本 HTML。它属于基础设施派生数据维护，接口层解析命令，部署入口分派，基础设施负责渲染和数据库事务。命令不加载网站配置或主题，不初始化业务角色；沿用运行数据库连接，恢复隔离期间拒绝执行。

保留既有分批读取、事务外渲染、源文及编辑版本 CAS、媒体引用与审计原子提交。只在提交成功后计数，不增加编辑版本或改变业务更新时间；错误使当前进程失败，已完成记录可被下一次重跑跳过。

## 后果与限制

历史派生物故障不再阻止启动、迁移或预约发布，重建成本与故障归属变为明确的运维操作。正常保存仍生成当前规则的 HTML，公开读取继续使用已存储结果。

规则升级需要部署流程显式安排重建。涉及清洗安全修复时，应在恢复公开访问前完成；不能依赖重启自动使全站内容采用新规则。本次不引入后台重建任务、启动版本门禁或全站快照，持续并发编辑仍通过逐记录 CAS 协调。

验证覆盖真实 CLI 和服务启动、三类内容重建、幂等重跑、失败修复后重试、恢复隔离，以及已有并发编辑和审计回滚测试。
