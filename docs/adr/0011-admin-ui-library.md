# ADR-0011：后台 UI 迁移到 Ant Design v6

- 状态：已采纳
- 记录日期：2026-09-23
- 关联决策：[ADR-0012：前端公共取数与错误处理](0012-admin-data-layer.md)、[ADR-0013：TanStack Query](0013-tanstack-query.md)
- 当前参考：[后台开发约定](../admin-development.md)、[身份、权限与后台](../identity-and-admin.md)

## 背景

后台原为 React、TypeScript、Vite 加手写 CSS，列表、表单、确认弹窗和操作反馈由各屏自行实现。继续扩展会重复处理中文文案、交互状态、布局和可访问性。用户明确不要求保留原有样式，因此没有继续维护整套视觉组件的必要。

公开站点使用 Rust 与 MiniJinja SSR，和后台没有共用组件的要求。后台 UI 选型可以独立进行，但不能改变已有权限、乐观锁和编辑器的保存语义。

## 决策

采用 Ant Design v6，保留 React、TypeScript 和 Vite。使用组件库提供的表单、列表、上传、弹窗和布局能力，不同时引入另一套后台框架。

主题、中文 locale 和上下文组件由统一 Provider 提供；视觉调整以 token 和公开的语义插槽为边界。后台跟随系统深浅色，公开站点主题仍独立管理。先使用默认运行方式，不引入需要额外静态 CSS 生成工序的 `zeroRuntime`。

迁移分两步：先替换 UI，再独立评估取数层。UI 迁移必须保留字段基线比较、请求期间输入合并、版本冲突处理和后端字符计数规则，不能用组件库的 touched 状态或通用校验替代业务语义。

## 考虑过的方案

- **继续手写样式，或采用 Headless 组件**：保留外观自由，但仍需自行组合布局、视觉与反馈。在不保留原样式的前提下，这部分成本没有足够收益。
- **Mantine**：也是完整组件库候选；当时评估需要额外组合表格、上传反馈与中文化配置，未优于直接采用 Ant Design。
- **Ant Design Pro、refine、react-admin 等后台框架**：已有路由、权限与写入语义需要适配其资源抽象，部分方案还改变构建或服务端栈。当前收益不足以抵消迁移成本。
- **Tailwind 或 shadcn/ui**：需要另行接受并维护一套样式与组件体系，未与本次组件库迁移并行引入。
- **同时更换正文编辑器**：正文仍采用 Markdown；编辑能力与前后端渲染一致性需独立评估，不由 UI 库选型决定。

## 后果与限制

组件交互和中文化有统一来源，但后台更依赖组件库的主题、异步交互及升级约定。定制应使用公开接口，避免依赖内部 DOM 结构。

组件库增加前端体积。路由懒加载可以隔离屏幕代码，不能消除共享组件库的成本；是否进一步拆包应依据构建结果和加载需求判断。

测试需要覆盖用户可见结果和真实交互时序。组件库会改变弹窗、表单校验和提交的调度方式，不能把旧的同步 DOM 假设当作业务契约。
