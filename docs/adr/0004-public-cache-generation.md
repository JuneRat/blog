# ADR-0004：公开内容 generation

- 状态：提议
- 记录日期：原记录未注明
- 关联决策：[ADR-0002：模板数据函数](0002-template-data-functions.md)、[ADR-0015：持久化 HTML 与渲染](0015-rendered-content-runtime-and-module-boundaries.md)
- 当前参考：[主题与渲染](../themes-and-rendering.md)、[功能路线](../product-roadmap.md)

## 背景

模板数据函数可能产生动态列表依赖。若启用跨请求公开页面缓存，需要统一的失效方式，避免发布或撤回后继续读取旧结果。

## 决策

提议使用站点级公开内容 generation：业务公开结果变化时在数据库事务中原子递增，页面按 generation、主题、设置和模板 API 版本寻址。

启用前应验证发布期间的命中率、整体延迟、重建并发和撤回语义，再决定采用站点级版本还是细化失效范围。未通过这项验证前可以保持不启用页面缓存。

## 考虑过的方案

暂不启用页面缓存、按集合版本或依赖标签失效，以及记录运行时查询依赖，均是可选方案。站点级版本实现较简单，但任意公开变更都可能使全站缓存变冷，并让写事务竞争同一版本记录。

## 后果与限制

generation 不是领域聚合，也不单独保证立即撤回。读端版本新鲜度、正文查询隔离、并发请求的可见性时点和 CDN 策略必须一起定义。正文输出前后的版本检查只能缩小竞态范围，不能撤销已发送字节。

## 后续变更

2026-09 的[桥接原型](../template-bridge-experiment.md)验证了请求级查询缓存与函数预算的配合，但没有替代跨请求缓存的失效验证。本提议尚未实施；持久化 HTML、Markdown 结果缓存和请求级查询缓存均不表示已启用整页缓存。
