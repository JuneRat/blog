# ADR-0020：固定后台任务、持久计划与跨进程租约

- 状态：已采纳
- 记录日期：2026-09-30
- 关联决策：局部替代 [ADR-0019](0019-admin-html-maintenance.md) 的进程内任务状态和去重方式，扩展 [ADR-0016](0016-confirmed-blog-schema.md) 的运行表；沿用 [ADR-0017](0017-explicit-html-rebuild.md) 与 [ADR-0018](0018-bounded-html-maintenance.md) 的显式 HTML 重建和批次契约
- 当前参考：[后台任务操作](../operations-and-recovery.md#后台任务管理)、[权限](../identity-and-admin.md#7-后台与可观测边界)、[数据库实现](../database-current.md#后台任务与计划)

## 背景

后台 HTML 重建已有短请求、进度和逐记录事务，但计划、结果和进程内去重不能跨服务重启保留。管理员还需要查看自动发布、控制保留期维护和安排一次重建。三类任务应共用执行记录、取消和生命周期，同时保留各自业务规则与数据库身份。

## 决策

仅支持 `html_rebuild`、`retention`、`publish_due` 三种固定任务，不接受命令文本、任意处理器或 cron 表达式。新增 `task_runs` 保存执行状态、报告和租约，`task_schedules` 保存固定计划。迁移只创建结构，不插入计划；正常服务确认安装完成后幂等准备默认计划，安装预检和恢复核验不写入这些运行表。

HTML 支持立即执行或一年内未来时间的一次性计划，每轮仍为 100 条 × 100 批，三类正文来源共用额度。保留期任务支持 1 小时至 30 天的固定间隔，默认每天一次且未启用；启用、停用与既有保留天数分别管理。预约发布固定每 30 秒检查且默认启用，保留启动后处理到期积压的语义，不允许从后台改成任意周期或关闭自动发布。

应用层定义任务种类、参数、授权、状态与端口，复用现有 HTML、保留期和到期发布用例；HTTP 只持久接受请求或读取状态。server 的统一监督器持有调度、取消、续租及 worker，不再并行运行另一套预约发布定时器。正常启动与安装后的 Router 激活使用同一监督器，安装初始化提交前不得执行任务。

每种任务只能存在一个活动执行，重复启动返回已有活动任务。跨进程领取和状态变更使用数据库时间与租约 token；续租、进度和终态更新均校验当前持有者。业务写事务内也锁定并核验租约，失去租约的旧 worker 不能提交后续变更。HTML 渲染继续在事务外，原逐记录 CAS、引用和审计原子提交契约保留。

同步进度观察者只替换最新快照，由受控异步 writer 串行持久化；不会每次进度创建独立任务。报告仅统计已确认部分，进度保存可能落后于已提交记录，未知剩余量保持 null。完成状态与最终报告通过有租约条件的写入保存；失败消息不返回数据库诊断或源文。

`queued` 计划和历史跨重启保留。正常服务会继续领取已到期的 queued 任务；已经运行的任务若租约过期则变为 `interrupted`，不自动重试。管理员重试会生成新 ID，根据当前业务数据处理剩余工作。网页取消仅接受尚未执行的手动、一次性计划或重试请求，运行中取消返回 409；中断或失败都不撤销此前已提交的业务记录。关闭浏览器不取消服务端执行；服务关闭时停止领取，取消并回收在途 worker，在关闭期限内保存可确认结果后关闭连接池。

每种任务保留最新状态，终态历史最多 500 条，活动记录不参与历史修剪。执行历史和 `audit_logs` 职责不同：前者用于进度、计划和重试，后者继续证明业务事务提交，并遵守独立的审计保留期。

后台任务管理复用 `settings.manage` 与现有 CSRF、Origin、可信来源 IP 边界。HTML 使用业务连接；保留期复用既有可选维护连接或默认站点连接，不向受限运行账号增加审计删除权限。显式维护连接不可用时禁用后台清理能力，不阻止站点登录；错库由业务事务中的任务租约核验拒绝。配置专用连接意味着 HTTP 进程持有该角色限定的维护能力。恢复配置或数据库隔离期间只能读取，禁止初始化计划、领取、取消、重试、续租或更新进度；正常模式解除隔离后才恢复调度。

## 后果与限制

管理员可在独立任务页面查看三类任务、最新状态和有界历史，并安排、取消或重试允许的执行。持久计划改变了 ADR-0019 的重启边界，但普通启动仍不自动创建 HTML 重建请求；只有已明确提交的 queued 请求会继续执行。

CLI 的 `rebuild-html`、`maintenance`、`publish-due` 保持独立入口，不进入任务队列或任务租约。它们与后台并行时仍依赖原有 HTML CAS、发布状态条件及清理事务锁；任务租约不表示所有 CLI 与服务操作的全局互斥，也不提供跨资源 exactly-once 承诺。

此机制不使认证限流、OAuth 一次性状态或整站部署具备完整多实例能力。备份、恢复、升级和媒体物理清理仍需要停止全部写入者；恢复的 queued 计划及周期配置必须纳入重新开放前的核对。验证应覆盖实际任务执行、跨进程竞争、旧 token 拒绝、安装激活、重启/取消/重试、历史上限、受限维护权限和恢复模式零任务写入。
