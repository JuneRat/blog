# ADR-0019：后台显式 HTML 重建与服务进程单任务

- 状态：部分被替代；持久计划、历史与跨进程执行协调见 [ADR-0020](0020-persistent-admin-tasks.md)
- 记录日期：2026-09-30
- 关联决策：扩展 [ADR-0017](0017-explicit-html-rebuild.md) 的显式执行入口，沿用 [ADR-0018](0018-bounded-html-maintenance.md) 的批次预算、逐记录提交和部分完成契约
- 当前参考：[运维](../operations-and-recovery.md#在管理后台执行)、[主题与渲染](../themes-and-rendering.md#正文渲染与持久化)、[后台权限](../identity-and-admin.md#7-后台与可观测边界)

## 背景

规则升级后，管理员需要在管理后台查看旧派生物数量并明确执行重建。既有 CLI 用例已提供有界预检、CAS 和逐记录事务，但完整执行可能超过 HTTP 请求期限；将 CLI 或重建 future 放在长 HTTP 请求内，会把执行生命周期绑定到连接与超时。

## 决策

新增后台「站点设置 → 内容维护」入口，复用 `settings.manage`。GET 读取待重建数量和最近任务，POST 在服务端接受任务后快速返回 202；认证、CSRF、Origin 和来源 IP 沿用现有后台边界，不通过 shell 启动 CLI。

应用层定义后台授权、任务端口、状态 DTO 和同步进度观察接口，仍不依赖 Tokio。CLI 保留原 `run` 入口和报告。server 管理任务句柄与内存状态，website 装配 PostgreSQL 适配器、可信审计上下文与已有渲染运行时。正常启动和安装完成后切换 Router 共用同一个进程协调器；安装预检不启动重建任务。

后台固定每批 100 条、最多 100 批，三类共用额度。一个服务进程只接受一个运行任务，重复启动返回当前任务，不排队；仅保存最近任务。进度记录已确认提交、跳过及批次数，失败保留此前已完成部分；未知剩余量为 null，不把初始统计当成实时总量。后台报告不暴露数据库内部诊断。

关闭浏览器不取消任务，刷新可继续查询。服务关闭时停止接收新任务，取消在途任务并等待任务句柄退出，再关闭数据库连接池；中断和失败不记为正常完成。重启不恢复内存任务，不自动执行维护；管理员依据数据库当前待处理量再次启动，已完成记录自动跳过。

配置恢复模式和数据库隔离标记都禁止重建，执行期间在批次前复核隔离。每条 HTML、媒体引用和审计同事务生效，后台记录启动者与可信来源 IP，CLI 使用系统来源；业务编辑版本、更新时间和发布状态不改变。

## 后果与限制

管理员可以从后台分次完成规则升级，执行不会因浏览器离开而中止。正常完成只表示本轮结束，达到额度或并发跳过后仍须查看 `has_more`。

不新增 schema、持久任务队列或全局任务锁。进程内去重不能阻止其他实例或 CLI 同时重建；现有源文、业务版本与派生版本 CAS 使竞争者跳过已更新记录，不覆盖并发编辑或重复提交同一版本的审计，但仍可能重复渲染。统计与批次各用独立快照，不提供全站冻结或生产耗时承诺。

验证覆盖授权与请求安全、安装后动态启用、短请求与进度读取、页面刷新、部分失败重试、审计来源、恢复隔离和关闭/重启行为；实际验收证据由运维验证记录保留。

## 后续变更

[ADR-0020](0020-persistent-admin-tasks.md) 用持久执行记录、一次性计划、跨进程租约及统一监督器替代本篇的内存唯一事实和进程内去重。后台入口迁至独立任务页面；queued 请求跨重启保留，已运行任务过期后中断且需明确重试。显式执行、短 HTTP 请求、业务 CAS、共享渲染运行时和同事务审计继续有效；CLI 仍独立执行，不进入任务队列。
