# ADR-0006：共享内容存储与可验证引用

- 状态：已被替代
- 记录日期：2026-09-21
- 关联决策：由 [ADR-0007](0007-simple-separated-content-schema.md) 替代；后续核心模型见 [ADR-0008](0008-thirteen-table-blog-core.md)
- 当前参考：[数据库设计](../database-design.md)、[内容生命周期](../content-lifecycle.md)

## 背景

用户要求推荐数据库表与字段设计。当时的方案需要同时表达 Post/Page 的工作副本、发布修订、历史路径和可验证的媒体引用。以下保留当时建议，不作为当前 schema。

## 决策

建议 Post/Page 在 PostgreSQL 共用 `contents`、`content_working_copies`、`content_revisions` 和 `content_paths`，通过不可变 kind 区分。领域模型和发布用例仍保留类型边界，共用表不要求合并聚合。发布指针采用同内容复合外键，历史媒体、分类关系使用真实外键。

媒体保留引用采用限定宿主列及互斥 CHECK，避免无外键的任意 `owner_type/owner_id`。公开媒体引用由当前发布指针和活动设置推导为视图，发布事务改变指针即改变公开引用；不预建独立可写计数作为授权依据。

## 考虑过的方案

- Post/Page 各建一套表：可隔离未来不同字段，但在当时的修订模型下会重复修订、路径及媒体关系，或需要额外身份登记层。
- 单独持久化公开引用集合：有读取优势，但需维护另一套与内容、设置同步的权威状态。当时没有读性能证据支持承担这份维护成本。

## 后果与限制

共享表中的类型特定约束需要显式验证；生命周期明显分化时可能需要子类型表或拆分迁移。媒体引用增加宿主需要修改关系约束。视图仍有查询成本，需要合适索引和测量；只有压测表明必要且事务方案得到验证后，才考虑物化公开引用。
