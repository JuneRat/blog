# ADR-0006：共享内容存储与可验证引用

记录日期：2026-09-21。

状态：被 [ADR-0007](0007-simple-separated-content-schema.md) 替代。用户随后明确要求精简 DDL、保留 RBAC/OAuth 并分开 Post/Page；下文仅保留当时的提议，不再作为当前实施方案。原来源：用户要求推荐数据库表与字段设计。

建议 Post/Page 在 PostgreSQL 共用 contents、content_working_copies、content_revisions 和 content_paths，通过不可变 kind 区分。领域模型及发布用例保留类型边界，表的复用不表示必须合并 Post/Page 聚合。发布指针采用同内容复合外键，历史媒体/分类关系使用真实外键。

媒体保留引用采用限定宿主列及互斥 CHECK，避免无外键的任意 owner_type/owner_id。公开媒体引用先通过当前发布指针和活动设置推导为视图，发布事务改变指针即改变公开引用，不预建独立可写计数作为授权依据。

替代方案包括 Post/Page 各建一套表，以及单独持久化公开引用集合。前者可隔离未来不同字段，但当前会重复修订、路径和媒体关系，或引入额外身份登记层；后者有读取优势，但需维护一套与内容/设置同步的权威状态。暂不为尚未验证的读性能承担重复状态维护。

代价：共享表的类型特定约束需要显式验证，未来生命周期明显分化时可能需要子类型表或拆分迁移；媒体引用增加宿主需要修改关系约束。视图访问需要合适索引和测量，不宣称免除查询成本。只有压测表明必要且事务方案已验证时，再物化公开引用。

当前字段、索引、删除和迁移顺序以 [精简数据库设计](../database-design.md) 为准，其中已不再使用本提议的共享内容表。
