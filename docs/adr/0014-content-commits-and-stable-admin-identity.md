# ADR-0014：领域写入口、完整内容提交与后台稳定身份

状态：已采纳并实现。日期：2026-09-26。

## 背景

项目处于开发阶段，业务规则、内容提交和资源身份需要收敛为单一契约，本次重构不保留旧接口兼容层。

原创建用例直接修改 PostSnapshot 的系列等业务字段；编辑才执行领域校验。原文章保存已经在同一事务维护正文、标签、系列版本和媒体引用，但端口只表达 snapshot 和标签，部分响应还在提交后另查标签。后台路由使用可改名、可复用的 slug，编辑器需要跟踪改名后的地址。

## 决策

### 领域写入口

- PostDraftMetadata 表达创建时的分类、系列和封面；创建与编辑共用 SeriesPlacement 的正整数规则。
- Post::trash/restore 决定 deleted_at 与恢复状态；归档保持归档，其余恢复为草稿，首次发布时间和 slug 锁定继续保留。
- 应用层通过聚合行为产生写入，不修改快照的业务字段。PostRepository/PageRepository 的写方法接收 Post/Page；快照用于查询、提交结果与持久化还原。
- PostgreSQL 适配器的快照写方法只作为私有实现；存储契约测试通过领域聚合提交。验证数据库约束的非法数据测试直接使用 SQL，不为测试保留公开快照写入口。

### 一次提交与完整快照

- insert_post、commit_post 明确要求正文、标签、媒体引用和受影响系列版本同事务更新；保留既有系列锁序和 CAS。
- find_record_by_id 一条 SQL 读取正文、版本和排序后的标签，返回 PostRecord。
- commit_post/commit_lifecycle 在事务提交前、仍持有文章写锁时获取完整记录。提交成功才返回该记录；调用方不再在提交后回读标签拼装响应。
- Page 的提交返回本次写入对应的快照。外部文件与数据库之间仍沿用媒体状态机，不扩展为跨系统事务。

### 后台资源身份

- 内容管理接口统一使用 `/api/admin/v1/posts/{id}` 和 `/api/admin/v1/pages/{id}`；id 是 UUID。列表、创建和文章回收站同属 v1，不提供第二套版本。
- 编辑、发布、撤回、回收/恢复/永久删除都按 ID 定位，仍执行原有授权、CSRF、版本前提与媒体引用规则。
- 前端编辑路由为 `/admin/posts/{id}/edit`、`/admin/pages/{id}/edit`；列表、系列与媒体使用位置链接传递实体 ID。slug 改名不改变编辑会话身份。
- 公开 URL 继续使用 slug。管理 API 与应用仓储不提供 Post/Page 的 slug 定位入口；UUID 路径参数直接校验，不进行身份猜测或回退。
- CLI 对已有文章的查看、编辑、发布和撤回统一使用 `--id`；创建结果和列表展示 UUID。创建时的 `--slug` 与编辑时的 `--new-slug` 只设置公开地址。
- Page 删除路径已包含 ID，请求体只需 `expected_version`，移除重复的 `expected_id`。

## 范围

这是开发阶段的接口重构，无数据库迁移。旧 slug 管理路径、CLI 定位参数与公开快照写方法直接删除，前后端和测试同步采用新契约。单份正文的发布语义与公开 slug 路径保持不变。

本决策覆盖 Post/Page 的身份与提交契约；分类、标签、系列目录使用各自的既有接口。

## 验证

- 领域：创建与编辑拒绝相同的非法系列位置，回收/恢复规则和归档终态一致。
- PostgreSQL：完整提交结果、媒体引用失败整体回滚、并发正文与标签同快照、生命周期 CAS。
- HTTP：改名及 slug 复用后仍操作同一 ID；已删除 ID 不指向新占位实体；原权限、CSRF 与冲突规则继续成立。
- 前端：按 ID 加载/保存/发布/冲突重载，改名不换编辑地址；请求期间新增输入与未保存保护保留。
