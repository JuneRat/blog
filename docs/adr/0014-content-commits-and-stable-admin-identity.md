# ADR-0014：领域写入口、完整内容提交与后台稳定身份

- 状态：部分被替代
- 记录日期：2026-09-26
- 关联决策：由 [ADR-0015](0015-rendered-content-runtime-and-module-boundaries.md) 扩展正文派生物与渲染边界；归档与恢复规则由 [ADR-0016](0016-confirmed-blog-schema.md) 局部替代
- 当前参考：[内容生命周期](../content-lifecycle.md)、[数据库设计](../database-design.md)、[管理 API](../admin-api.md)

## 背景

创建文章的用例曾直接修改 `PostSnapshot` 中的系列等业务字段，只有编辑路径执行相应领域校验。文章保存虽然已经在同一事务维护正文、标签、系列版本和媒体引用，但端口只表达快照与标签，部分响应还在提交后另查标签，不能保证组合出的响应属于同一次提交。

管理路由使用可改名、可复用的 slug，编辑器需要跟踪改名后的地址。项目处于开发阶段，可以同步调整前后端与 CLI，直接统一内容身份和提交契约。

本记录包含三个相关选择：领域写入口、内容提交结果和管理资源身份。范围为 Post/Page；分类、标签和系列目录保留各自的管理接口。

## 决策

### 领域写入口

通过聚合行为创建或改变内容，仓储写端口接收 `Post` / `Page`。快照只用于查询、提交结果和可信持久化还原，不作为应用直接修改业务字段的写入入口。

文章创建元数据与编辑共用系列位置校验；回收与恢复由聚合决定删除时间和恢复状态。归档保持终态，其余恢复为草稿，首次发布时间与 slug 锁定继续保留。

适配器内部的快照写方法保持私有。仓储契约测试通过聚合提交；需要验证数据库拒绝非法状态时直接使用 SQL，不为测试保留公开的绕过入口。

### 内容提交与返回结果

一次文章提交原子更新正文、标签、媒体引用和受影响的系列版本，继续使用固定锁序与版本条件写入。

读取文章时，以一次查询取得正文、版本和排序后的标签，组成完整记录。保存或生命周期操作在事务提交前、仍持有文章写锁时取得本次记录，提交成功后返回；调用者不在提交后另查关系再拼装响应。Page 同样返回本次提交对应的快照。

### 管理资源身份

Post/Page 管理 API 与后台编辑路由使用不可变 UUID；Post CLI 对已有文章的查看、编辑、发布和撤回也使用 ID。slug 只决定公开地址，草稿改名不会改变管理资源身份。

开发阶段直接替换旧 slug 管理入口，统一使用管理 API v1，不增加兼容路径或自动猜测 ID/slug。页面删除由路径提供唯一身份，请求体仅提供版本前提。具体路由与载荷由[管理 API](../admin-api.md)维护。

## 考虑过的方案

这些取舍对应改动前的实现方式：

| 原有方式 | 调整原因 |
|---|---|
| 应用直接修改快照再提交 | 创建与编辑可经过不同校验路径，规则容易被绕过 |
| 提交成功后再查询标签拼装详情 | 后续并发写入可能让正文与标签来自不同提交 |
| 用 slug 定位后台资源并追踪改名 | 可变路径与稳定身份耦合，地址复用后还需防止误操作新实体 |

## 后果与限制

- 创建、编辑和生命周期操作共享领域规则，仓储端口承担明确的原子提交及返回值契约。
- 管理资源身份稳定，但旧客户端、CLI 参数和测试必须同步调整；此次接口重构没有数据库迁移。
- 仍采用单份当前正文，保存已发布内容直接更新线上。UUID 管理身份不改变公开 slug 锁定或路径释放规则。
- 外部文件和数据库继续由媒体状态机协调，不扩展为跨系统原子事务；公开快照的可信重建也不替代输入校验。

验证重点是创建/编辑规则一致、失败整体回滚、正文和关系来自同一快照，以及改名或地址复用后仍操作正确 ID。测试入口见[开发指南](../development.md)，当前实现边界见[架构](../architecture.md)。
