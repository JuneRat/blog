# ADR-0015：持久化 HTML、集中渲染与按命令装配

- 状态：部分被替代
- 记录日期：2026-09-26
- 关联决策：扩展 [ADR-0014](0014-content-commits-and-stable-admin-identity.md) 的内容提交；细化 [ADR-0001](0001-workspace-boundaries.md) 的依赖约束和 [ADR-0002](0002-template-data-functions.md) 的执行边界；[ADR-0016](0016-confirmed-blog-schema.md) 将持久化 HTML 扩展至受限 Markdown 评论
- 当前参考：[架构](../architecture.md)、[主题与渲染](../themes-and-rendering.md)、[配置](../configuration.md)、[数据库设计](../database-design.md)
- 后续替代：[ADR-0017](0017-explicit-html-rebuild.md) 将启动、内容命令与完整迁移中的自动重建改为显式 HTML 维护，保留持久化和事务规则。

## 背景

公开读取曾在每次请求中把 Markdown 转换并清洗成 HTML；保存时为解析媒体引用又执行同样的转换。主题的信号量、超时和阻塞调度放在应用用例内，执行策略与业务编排耦合。

CLI 的账号维护和内容命令共用完整网站装配，主题或网站配置故障会影响维护。端口与 PostgreSQL 实现集中在大文件中，分层依赖主要靠文档约定。

本记录保留同次重构的四项选择：正文派生物持久化、统一渲染执行、按命令装配、模块与依赖约束。它们各有独立边界，后续可以分别更新。

## 决策

### 正文派生物持久化

Post/Page 保留 Markdown 源文，新增 `content_html` 与 `content_render_version`。HTML 是服务端生成并清洗的派生物，不进入领域聚合，也不接受客户端赋值。

正文转换与媒体 ID 提取使用同一份清洗结果，在事务外的受控任务中完成。渲染结果只包含正文图片 ID，封面由仓储合并，不进入按源文缓存的结果。仓储把源文、HTML、渲染版本及媒体引用一起条件提交，并保持既有标签/系列关系的事务边界。公开详情直接读取已保存的 HTML。

渲染规则版本用于识别需要重建的记录。完整迁移分批读取、渲染，再以源文和业务版本为条件更新 HTML 与引用，避免覆盖并发编辑；重建不递增业务版本或修改业务更新时间。初次引入字段时使用 `0008_content_html.sql`；该历史文件现已由 [0001_initial_schema.sql](../../migrations/postgres/0001_initial_schema.sql) 取代，新库从建表起要求有效 HTML 和正整数渲染版本。

### 统一渲染执行

应用层定义异步正文与主题渲染端口，负责主题选择和业务数据，不承担 Tokio 调度。

基础设施运行时统一限制正文转换、引用提取和主题渲染的并发与等待时间。许可由实际执行的阻塞任务持有到退出；调用者取消或超时不会提前释放仍被工作占用的名额。

Markdown 缓存同时受条目数和字节数限制，仅存完整源文决定的 HTML 与引用；主题页面、数据库结果和媒体权限不进入该缓存。具体预算、模板限制和日志字段由[主题与渲染](../themes-and-rendering.md#执行策略与实际预算)维护。

### 按命令装配

server 根据命令构造所需的身份、内容、媒体或网站依赖。OAuth 维护与浏览器登录用例分开，账号和绑定维护不需要网站回调配置或模板。

只有 `serve` 解析网站专用配置、加载主题和静态资源。HTTP 路由组合属于 interfaces，监听和退出生命周期属于 server。

结构迁移与正文派生物重建分开：身份和媒体维护仅要求结构就绪；显式迁移、内容命令和网站启动执行完整迁移。派生物重建异常不应阻止密码重置。具体命令范围见[配置参考](../configuration.md#命令配置边界)。

### 模块与依赖约束

应用端口和 PostgreSQL 实现按业务模块拆分，入口明确导出公开契约，行映射、锁和 SQL helper 保持限定可见性；继续使用原有五个 crate。

CI 与本地检查通过 Cargo metadata 检查项目依赖方向和内层第三方依赖白名单，覆盖普通、构建、开发及条件依赖，区分生产边界与测试例外。当前模块布局和检查范围见[架构](../architecture.md)。

## 考虑过的方案

| 原有方式 | 调整原因 |
|---|---|
| 每次阅读时转换 Markdown，保存时再次转换以提取引用 | 重复计算，公开读取仍依赖正文转换成功 |
| 由应用用例直接管理信号量、阻塞池和超时 | 执行策略渗入应用层，不同渲染入口容易出现不同的预算语义 |
| CLI 共用全站依赖装配 | 无关网站故障会阻止账号维护，命令依赖范围不清晰 |
| 集中大文件并仅靠文档约束依赖 | 公开边界难以检查，违规依赖不能及时在 CI 中失败 |

## 后果与限制

- 持久化 HTML 增加存储量和规则升级时的重建成本，换取公开请求减少重复转换。业务更新时间不记录派生物重建，规则版本单独承担该职责。
- 阻塞任务不能被强制终止；等待超时不是硬 CPU 或内存隔离。许可、模板预算和有界缓存需要共同发挥作用。
- 增加窄装配函数和内部模块的维护成本，换取可辨识、可检查的依赖方向。检查脚本不能证明全部传递依赖或业务语义隔离。
- 没有引入跨请求整页缓存，也没有改变发布、可见性与删除条件。应用层异步端口本身不代表任意模板已经具备安全沙箱。

验证覆盖 HTML 与引用同事务、旧版本重建与并发编辑竞争、取消后的许可生命周期、缓存边界、维护命令隔离以及依赖检查器。执行方式见[开发指南](../development.md)。

## 后续变更

[ADR-0017](0017-explicit-html-rebuild.md) 替代本篇“完整迁移及网站/内容命令自动重建”的执行边界。结构迁移与 HTML 重建改为独立入口，规则升级由部署流程显式执行；同次保存、CAS、引用同步、审计及渲染预算原则继续有效。

[ADR-0016](0016-confirmed-blog-schema.md) 保留本篇渲染与分层原则，将源文、清洗 HTML 和渲染版本的同事务持久化扩展到评论。正常记录不保留 NULL/版本 0 的待渲染占位，文章、页面和评论按各自规则版本重建；当前契约见[主题与渲染](../themes-and-rendering.md)，交付与验收状态统一见[路线图](../product-roadmap.md#已采纳数据库设计的实施)。

后续调整缓存类型、派生物重建方式、执行策略归属或命令装配边界时，新增决策并指明更新本记录的具体部分。单纯调整运行预算或内部文件布局，更新当前参考与测试即可，无需重排已有 ADR 编号。
