# ADR-0015：持久化 HTML、集中渲染与按命令装配

状态：已采纳并实现。日期：2026-09-26。

## 背景

公开读取原先每次把 Markdown 转换并清洗成 HTML；保存时为解析媒体引用又执行同样的转换。主题的信号量、超时和阻塞线程调度放在应用用例内。CLI 的账号维护和内容命令共用完整网站装配，主题或网站配置故障会影响维护。端口和 PostgreSQL 实现集中在大文件中，依赖方向只靠文档约定。

本次继续开发阶段的直接重构，不维护旧构造函数或重复的接口实现。

## 持久化派生 HTML

- `posts`、`pages` 新增 `content_html` 与 `content_render_version`，由迁移 `0008_content_html.sql` 创建。
- `content` 仍是 Markdown 编辑源文；HTML 是服务端渲染、清洗后的派生物，不进入领域聚合，不接受客户端直接指定。
- 内容仓储先经异步 `ContentRenderer` 生成 HTML，在同一受控阻塞任务中从该 HTML 提取正文图片引用，与封面取并集。源文、HTML、渲染版本、标签/系列和媒体引用在同一条件事务中提交；转换或引用检查失败不产生部分写入。
- 公开详情只查询已保存的 HTML，保持原有发布、可见性和删除条件。没有新增整页缓存，撤回后新请求仍立即失去公开访问资格。
- 渲染规则版本初值 0 表示待生成。完整迁移入口按批次重建不匹配版本的派生物，再允许内容服务启动。转换在事务外执行，写入同时检查源文和业务版本，避免覆盖并发编辑；HTML 和媒体关系一同提交，不递增业务版本或改变业务更新时间。
- 清洗或 Markdown 规则升级时递增 `CONTENT_RENDER_VERSION`，重新运行完整迁移。持久化 HTML 增加存储量，换取公开请求不再重复转换正文。

## 渲染执行边界

- application 只定义异步 `ContentRenderer`、`ThemeRenderer` 端口和展示数据；主题选择保留在公开站点用例。应用层不依赖 Tokio。
- infrastructure 的 `RenderingRuntime` 对 Markdown 和主题使用共享执行预算：默认 16 路并发、排队 250ms、结果等待 2s。
- 阻塞任务取得并持有许可直到实际退出。取消或超时只结束调用者等待，不能释放仍在执行的任务占用的并发名额，也不声称能强制终止阻塞线程。
- Markdown LRU 缓存上限为 64 项、源文、HTML 与媒体 ID 合计 8 MiB；超出大小的单项不缓存。运行日志记录命中、排队和执行时间、超时。MiniJinja 现有 fuel、递归、宿主查询和输出预算继续生效。

## 命令装配

- server 根据命令装配身份维护、内容管理、媒体维护或 HTTP 服务依赖，各命令接收所需用例，不再使用包含全站依赖的 `CliDeps`。
- OAuth 维护从登录用例中分离，维护提供商或账号绑定不需要构建网站回调配置和外部登录客户端。
- `serve` 才解析网站专用配置、加载主题与静态资源。路由组合属于 interfaces，监听和优雅关闭属于 server。
- `migrate_schema` 只执行 SQL，供身份/媒体维护使用；完整 `migrate` 另行生成 HTML，供显式迁移、内容命令和服务启动使用。正文派生物异常不能阻塞密码重置。

## 模块和依赖检查

应用端口拆为 content、identity、media、site、taxonomy、rendering、runtime；PostgreSQL 实现拆为对应业务模块及连接和 SQL 辅助模块。入口文件使用明确导出，内部行映射、锁和 SQL 辅助函数保持限定可见性。业务用例继续留在原有五个 crate 内。

依赖检查使用 Cargo metadata，覆盖生产、构建、开发以及条件编译依赖，区分生产白名单和测试例外；CI 和本地检查脚本都执行它。它检查项目内依赖方向及已声明的第三方准入规则，不声称能证明全部传递依赖和业务语义隔离。

## 验证

- PostgreSQL：Post/Page 保存与公开读取 HTML、清洗、失败回滚、过期写保护、已有数据库升级补齐和重建与并发编辑竞争。
- 渲染：取消及超时后的许可生命周期、过载、缓存条目/字节边界、主题共用门限与已保存 HTML 的传递。
- 装配：无效主题/网站配置不妨碍身份维护，启动网站仍校验主题。
- 依赖检查：合法依赖通过；反向边、依赖别名、构建依赖、条件依赖及越界开发依赖被拒绝。
