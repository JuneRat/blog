# ADR-0016：确认新的博客数据库设计与独立会话版本

- 状态：已采纳
- 记录日期：2026-09-26
- 关联决策：局部替代 [ADR-0008](0008-thirteen-table-blog-core.md) 的内容关系、删除及扩表选择，[ADR-0009](0009-local-password-authentication.md) 和 [ADR-0010](0010-persistent-postgres-sessions.md) 的用户版本会话绑定，[ADR-0014](0014-content-commits-and-stable-admin-identity.md) 的归档与恢复规则；扩展 [ADR-0015](0015-rendered-content-runtime-and-module-boundaries.md) 的持久化 HTML 范围
- 当前参考：[目标数据库设计](../database-design.md)、[目标 DDL](../sql/postgres-core.sql)、[当前数据库实现](../database-current.md)、[实施路线](../product-roadmap.md#已采纳数据库设计的实施)

## 背景

用户提供新的数据库草稿，并逐项确认媒体、系列关系、版本、正文、评论、身份、设置与审计的取舍，随后要求加入 sessions。目标是保持单站点博客的简约模型，不为旧设计建立兼容层，同时明确哪些规则由数据库约束、哪些由应用事务保证。

当前实现已从最初的 13 表扩展到包含媒体、会话和评论的 19 表。本次目标也为 19 表，但移除了两张评论设置表，新增 post_series 和 audit_logs，并改变了部分字段、引用和生命周期，不能把相同表数当作结构兼容。

## 决策

以目标 DDL（现保存为 docs/sql/postgres-core.sql）和目标数据库设计文档作为已采纳方案，保留 18 张业务表与独立 sessions。实施采用可重建空库：原九个迁移由一个新初始基线替换，不做旧数据转换或兼容；第一批同步身份、RBAC、sessions 和审计追加基础，后续媒体、内容、评论与恢复适配在路线图跟踪。

- 媒体链接独立公开，私密文章不限制媒体 URL。保留 media_refs 查询使用位置和保护物理删除；软删除保留文件和链接，零引用不自动回收，因为引用表无法覆盖站外使用。
- 文章与系列采用 post_series 多对多，position 为可重复的非负权重；分类保留单归属与树结构，标签/系列删除只清理关联。
- 编辑 version、认证 auth_version、HTML 渲染规则 content_render_version 分开存列。会话保存 auth_version 快照；资料编辑不使会话失效，角色权限在受保护请求中实时重读。
- Post/Page 只接受 Markdown；评论采用受限 Markdown。三者都持久化服务端清洗后的 HTML 与正整数渲染版本，和源文同事务提交；派生重建不算业务编辑。
- Post/Page 增加 scheduled，首次预约或发布锁定 slug，published_at 同时承担预约及展示时间。归档可以回到草稿，回收站恢复统一回草稿；Page 没有作者，采用全站权限并具有回收站。
- 评论允许多级回复，parent_id 指向直接对象，root_id 指向根，前端平铺成两级。删除保留后代和必要占位；状态采用 pending/approved/spam/trash。移除评论去重、提交频率限制及对应字段；开关合并到 settings.comments 和 posts.comments_enabled。
- 用户名/邮箱按不区分大小写唯一；用户有独立状态和纯文本 bio。OAuth 使用 provider/subject 复合身份，角色使用稳定 code，权限直接以 code 为主键。账号停用不改变已发布内容和媒体的公开性。
- settings 按组保存非敏感覆盖值。成功业务变更与 audit_logs 同事务提交；评论来源 IP 和审计日志默认保留 180 天，前者到期清空 IP，后者由维护身份清理。公开响应不返回评论邮箱或 IP。
- sessions 使用随机令牌的 SHA-256 摘要作主键，保存独立 CSRF 值、用户、auth_version 快照及创建/活跃/绝对过期时间。鉴权同时检查用户状态、版本与空闲/绝对期限；活跃刷新不得延长绝对期限或更新认证快照，恢复备份后撤销旧会话。

## 考虑过的方案

| 方案 | 取舍 |
|---|---|
| 只存媒体表，清理时扫描全站 | 写入简单，但使用位置查询和删除保护需要反复扫描，且仍看不到站外使用；因此保留 media_refs |
| 通过引用文章的公开性控制图片访问 | 可以随文章撤回限制图片，但每次读取依赖来源判定；选择独立公开以简化访问，接受私密文章中的媒体仍可通过链接读取 |
| 沿用文章单系列与唯一章节号 | 无法将文章放入多个系列，重排需要维护位置唯一；改为多对多与稳定的重复权重排序 |
| 将版本混入 metadata 或共用 users.version | 编辑冲突、会话撤销和渲染重建具有不同语义；独立列便于约束和条件更新 |
| 评论只存源文、读取时渲染 | 减少派生字段，但重复执行转换，也难以统一规则重建；采用与正文一致的 HTML 持久化方式 |

## 后果与限制

模型保留单份当前正文、Post/Page 分表、稳定 UUID 管理身份和业务事务提交边界。独立公开媒体减少读取鉴权依赖，但文章私密设置不能保护已知图片链接；保留引用表也不能证明零引用媒体没有外部使用。

数据库负责类型、外键、唯一性及行内 CHECK。多节点分类防环、评论根一致性、slug 锁定、定时发布、HTML 清理/重建、媒体物理清理及会话鉴权必须由应用实现。审计运行账号授权、保留期任务和可信代理解析也不由 DDL 自动建立。

目标结构会直接调整领域、仓储、API、前端、主题和恢复工具，不提供旧接口或旧模型兼容分支。新的初始迁移仅适用于空库，检测到旧结构时拒绝启动；不会自动覆盖运行中的数据库。开发验证先用独立空库，全部业务适配后再显式重建并切换原开发库。建表验证不代表应用流程、数据迁移或生产恢复已验收。
