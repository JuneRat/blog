# ADR-0009：启用本地密码认证（Argon2id + 限流 + 受控重置）

记录日期：2026-09-22。

状态：已采纳并实现。来源：用户要求在 M2 之后优先启用 `users.password_hash` 预留的本地密码能力，并明确要求一次补齐哈希参数、限流/锁定、重置与恢复、泄露处置。细化契约见 [本地密码](../identity-and-admin.md#5-本地密码)，运维处置见 [凭据泄露处置](../operations-and-recovery.md#6-凭据泄露处置)。

## 背景

13 表基线保留 `users.password_hash text`，但文档明确写着「首版不开放密码认证和恢复；将来启用时另行实现密码哈希、限流与恢复契约」（[ADR-0008](0008-thirteen-table-blog-core.md)、[database-design](../database-design.md)）。远程长期部署只有 OAuth 时会受制于外部身份服务可用性与绑定运维成本，因此需要本地凭据作为对等登录方式。

「加个哈希」不足以交付：口令存储、暴力破解防护、忘记密码、凭据泄露是同一能力的不同侧面，缺一项就不能对外宣称可用。

## 决策

1. **口令一律用 Argon2id（PHC 自描述字符串）**，参数取 OWASP 推荐的最小配置：内存 19456 KiB、迭代 2、并行度 1、输出 32 字节、16 字节随机盐。参数写入哈希字符串，登录成功时若发现存储参数弱于当前策略则用同一明文透明升级（`needs_rehash`）。选择 Argon2id 而非 bcrypt/PBKDF2：内存硬特性显著抬高 GPU/ASIC 离线爆破成本。
2. **不新增表**。`password_hash` 已存在，限流计数与会话一样放单实例有界内存存储（重启清空计数，不清空凭据）。这保持 13 表基线与「重启即失去运行态」的一致语义。
3. **登录失败不区分原因**。用户名不存在、密码错误、账号已停用都返回同一个 `invalid_credentials`；未知用户也执行一次等价开销的哈希校验，避免用文案或响应时间枚举用户名。
4. **限流按账号与来源地址两个维度，且采用预占式计数**：账号 5 次/15 分钟、来源地址 50 次/15 分钟。额度必须在哈希校验**之前**预占——只做事后计数（先检查、再校验、最后记失败）会留下 TOCTOU 窗口，N 个并发请求会在任何一次失败被记录前全部通过，一次突发就是 N 次爆破机会。在飞预占与已确认失败共享上限；未得出结论就返回必须归还预占。锁定期间拒绝但**不延长**锁定（否则攻击者可用已知用户名把真实用户永久锁在门外）；锁定期满给一个干净的计数窗口。成功登录清空账号维度计数，来源地址维度只归还本次预占。
5. **重新认证与登录共用失败预算**：`POST /api/admin/v1/me/password` 校验「当前密码」同样先预占，被盗会话无法无限次试当前密码。
6. **凭据写入一律条件写入（CAS）**，包括透明升级、自助改密与 OAuth 用户设置初始密码（期望值为「当前必须为空」）。否则一次并发的自助改密就能把管理员刚下发的强制重置口令覆盖掉，泄露处置被静默撤销。
7. **「至少保留一种登录方式」与清除动作放在同一把身份排他锁内**：清除密码与解绑外部身份如果各自检查、各自写入，会双双看到「对方还在」而同时通过，把账号的登录方式清空（write skew）。这是与角色/Owner 保护同一类的不变量，必须靠锁而不是靠调用顺序。
8. **口令只在受控通道写入**。`blog user passwd --user <u>` 是设置/重置入口，交互终端隐藏回显并二次确认；也支持 `--password-stdin` 供自动化。**不提供 `--password` 参数**，避免口令进入进程表与 shell 历史。`--clear` 关闭密码登录，且与解绑外部身份同一条保护：不能移除账号的最后一种登录方式。
9. **改密即撤销会话**。受控设置/重置与自助改密都会撤销该用户全部会话；自助改密还会重签一个新会话下发给当前浏览器，所以当前会话之外（可能已泄露）的会话一并失效。自助改密必须由已认证会话发起并重新提供当前密码（`POST /api/admin/v1/me/password`）。
10. **登录与改密并发不互相覆盖**。除上面的 CAS 外，签发会话前还会复核凭据未被替换；并发改密后进行中的登录直接作废。否则登录升级会把刚换掉的口令重新写回，等于让旧口令复活。
11. **会话绑定签发时的身份修订号**（`users.version`），校验时重读比对。改密、改角色、软删除都会递增版本，因此**跨进程**动作（运维在另一个进程跑 `blog user passwd`）也能让运行中服务的旧会话立即失效——内存里的 `revoke_all_for_user` 在 CLI 进程里只是清空自己的空存储，对服务进程是空操作，光靠它无法兑现「改密即登出」。代价（有意接受）：任何递增 `users.version` 的动作都会登出该用户。
12. **自助找回不做半成品**。面向公众的邮箱找回需要一次性令牌存储、TTL 与原子消费、邮件投递和防枚举，且不能塞进 settings 伪装成表；本版明确不交付，重置只走部署权限的 CLI。泄露处置用「下发新口令 + 撤销会话」而不是清空口令绕开保护。

## 被否方案

- **把哈希拼进 `settings` 或新建 `password_reset_tokens` 表**：前者隐藏模型，后者需要一并设计令牌期限制、一次性消费与清理，不属于本次范围；不建空表也不假装具备。
- **bcrypt**：72 字节静默截断与较低的内存成本，不适合作为新系统的默认口令 KDF。
- **把口令哈希放进 `UserSnapshot`**：口令材料会随实体在用例间传播，扩大误用与误记录面；改用单独的凭据查询出口。
- **仅按 IP 限流或仅按账号限流**：前者在反向代理后误伤全体，后者挡不住跨账号撞库；两者都要。
- **成功登录清空所有维度计数**：攻击者可用自有账号反复清零来源地址计数，等于关掉 IP 维度。

## 代价与限制

- 单实例内存限流：多实例部署前必须换成共享存储，否则每个实例各自计数；当前不承诺多实例。
- 无自助找回：忘记密码只能由有 shell 权限的运维重置，用户侧无法自助完成。
- Argon2id 每次约 19 MiB，并发哈希用信号量限制（默认 4 路 ≈ 76 MiB 峰值）；高并发登录会排队而不是无限占用内存。
- 反向代理后的真实客户端地址需要部署侧显式配置可信转发，本版只信任 socket 对端地址，不读 `X-Forwarded-For`。
- 内存限流重启后清零，攻击者若能让进程重启即可重置计数；这是与内存会话一致的既有取舍。
- 并发边界：改密/改角色/软删除通过「会话绑定 `users.version`」跨进程生效，令牌签发前还会复核凭据未被替换，因此不存在「用已被换掉的口令建立会话」的窗口；改角色会让本人当前会话一并失效，这是撤权即时生效的必然代价。

后续变更：第 2 点「限流计数与会话一样放单实例有界内存存储」中关于**会话**的部分已由 [ADR-0010](0010-persistent-postgres-sessions.md) 更新——会话迁移到 PostgreSQL 的 `sessions` 表，重启后仍登录；登录失败限流仍为进程内存。第 11 点所述「内存 `revoke_all_for_user` 对另一个进程是空操作」不再适用于会话（共享存储后撤销本身即可跨进程生效），但 `users.version` 绑定继续作为纵深防御保留。本地密码的哈希、限流与重置契约本身不变。
