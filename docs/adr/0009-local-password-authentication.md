# ADR-0009：启用本地密码认证（Argon2id + 限流 + 受控重置）

- 状态：部分被替代
- 记录日期：2026-09-22
- 关联决策：更新 [ADR-0008](0008-thirteen-table-blog-core.md) 的密码预留选择；内存会话及撤销说明由 [ADR-0010](0010-persistent-postgres-sessions.md) 更新，用户版本绑定及角色变更失效由 [ADR-0016](0016-confirmed-blog-schema.md) 局部替代
- 当前参考：[本地密码](../identity-and-admin.md#5-本地密码)、[会话与失败限流](../identity-and-admin.md#6-会话与失败限流)、[开发指南](../development.md)、[凭据泄露处置](../operations-and-recovery.md#6-凭据泄露处置)

## 背景

[ADR-0008](0008-thirteen-table-blog-core.md) 保留 `users.password_hash`，但未开放本地密码认证。长期部署仅依赖 OAuth，会受外部身份服务可用性和绑定维护影响。用户要求优先启用本地凭据作为对等登录方式，并同时明确哈希、限流、重置与恢复、泄露处置。

口令存储、暴力破解防护、忘记密码处理和泄露后的撤销需要一起设计；仅增加哈希字段不足以形成完整的认证能力。

## 决策

1. **使用 Argon2id 与 PHC 自描述哈希**。利用内存成本提高离线猜测代价，随机盐与参数随哈希保存，允许成功登录后按当前策略重新生成。凭据经独立查询、写入端口流转，不进入普通 `UserSnapshot`。哈希在阻塞执行环境内运行，以信号量限制并发，避免登录突发耗尽内存；具体参数见现行[本地密码规则](../identity-and-admin.md#5-本地密码)。
2. **复用已有字段，本次不新增认证表**。当时会话和限流均使用单实例有界内存，重启会清除运行态，但不清除数据库中的凭据。会话部分后来由 ADR-0010 更新，限流仍保留此取舍。
3. **失败响应不区分用户名不存在、密码错误和账号停用**。未知账号也执行一次虚拟哈希校验，减少利用响应内容或耗时枚举账号的机会。
4. **账号和来源地址分别限流，校验前预占额度**。在途请求与已确认失败共享上限，防止多个并发请求在首次失败记账前全部通过检查。未完成验证的请求归还预占；锁定期间的拒绝不延长锁定，避免已知用户名被反复尝试永久锁住。成功验证清除账号历史失败，但不清除来源地址历史失败，避免攻击者用自有账号刷新地址预算。自助改密校验当前密码时共用同一失败预算。
5. **透明重哈希和自助改密使用条件写入（CAS）**。只能替换刚验证的旧凭据；OAuth 用户设置初始密码时要求当前值仍为空。否则并发自助改密或登录重哈希可能覆盖管理员刚下发的强制重置。签发会话前复核凭据未被替换，新会话绑定对应的身份修订号。
6. **清除密码与解绑外部身份共享身份排他锁**。检查剩余登录方式与删除凭据在同一事务完成，防止两条路径各自看见“另一种还在”而同时移除全部登录方式。
7. **管理重置走受控 CLI，自助改密走已认证会话**。CLI 采用隐藏输入或标准输入，不提供会进入进程表、shell 历史的明文密码参数。自助改密在已有密码时须重新提供当前密码，尚无密码时可凭有效会话设置初始密码。改密撤销该用户全部会话，自助改密再为当前浏览器签发新会话与 CSRF token。
8. **会话绑定签发时的 `users.version`**。校验时重读并比对，让改密、改角色等身份修订使旧会话失效。当时 CLI 和服务各自持有内存会话，CLI 只能撤销自身进程的存储，版本绑定因此也是跨进程失效的必要保障。
9. **不提供半成品的邮箱找回**。公开找回需要一次性令牌、期限、原子消费、邮件投递及防枚举；本次不建立空表，也不借 settings 隐藏模型。失去凭据由具备部署权限的运维重置，泄露处置采用换密与撤销会话，不通过清空最后一种登录方式绕过保护。

## 考虑过的方案

- bcrypt/PBKDF2：选择 Argon2id 的理由是内存成本；原记录还指出 bcrypt 的 72 字节输入限制，不将其作为新系统默认 KDF。
- 将哈希塞入 settings 或随 `UserSnapshot` 传递：前者隐藏模型，后者扩大凭据误用和误记录的范围。
- 本次一并增加 `password_reset_tokens`：需要完整设计令牌期限、消费和清理，超出受控重置范围，不能仅建表就宣称具备找回能力。
- 只按 IP 或只按账号限流：前者在代理部署下可能误伤全部用户，后者不足以限制跨账号猜测。成功登录同时清空两个维度也未采用，以免地址预算被已知账号反复清零。

## 后果与限制

本地登录减少对外部身份服务的依赖，但增加凭据保管、哈希计算和泄露处置责任。有限并发意味着高峰请求会排队；限流容量、阈值及口令策略属于现行规格，不在 ADR 重复维护。

登录限流是进程内状态，重启清空，各实例分别计数；完整多实例认证不在本决策范围。来源地址后续统一接入可信代理解析（2026-09-28）：只有指定代理的 `X-Forwarded-For` 生效，无法解析时限流回退 socket 桶；登录与自助改密共享规则。参见[身份与权限](../identity-and-admin.md#6-会话与失败限流)。

没有公众自助找回；运维必须保有可用恢复路径。用户身份版本变化会使既有会话在后续校验时失效，包括本人当前会话；这不意味着已经授权的在途业务请求会被取消。

## 后续变更

[ADR-0010](0010-persistent-postgres-sessions.md) 将本站会话迁移到 PostgreSQL。重启不再清除会话，按用户撤销也能直接作用于其他进程共享的会话记录；本篇关于“CLI 只能清除自身内存会话”的背景不再适用。当时继续保留 `users.version` 绑定，登录限流仍在进程内存。

[ADR-0016](0016-confirmed-blog-schema.md) 将目标会话绑定改为独立 `users.auth_version`。普通资料编辑不撤销会话，角色/权限变化通过请求实时重读生效；改密等认证撤销操作递增 auth_version。该调整已采纳，尚待代码实现；本地密码哈希、登录失败限流和受控恢复原则继续保留。

本地凭据、预占式双维限流、条件写入、最后登录方式保护和受控恢复的核心选择继续保留；接口载荷、CLI 参数和当前数值限制见页首专项文档。
