# ADR-0010：会话持久化到 PostgreSQL

- 状态：部分被替代
- 记录日期：2026-09-23
- 关联决策：更新 [ADR-0008](0008-thirteen-table-blog-core.md)、[ADR-0009](0009-local-password-authentication.md) 的内存会话选择；用户版本绑定由 [ADR-0016](0016-confirmed-blog-schema.md) 局部替代
- 当前参考：[会话与失败限流](../identity-and-admin.md#6-会话与失败限流)、[当前会话 schema](../database-current.md#7-持久会话)、[目标会话 schema](../database-design.md#7-持久会话)、[运行与恢复](../operations-and-recovery.md)

## 背景

初始模型将本站会话和 OAuth 尝试放在单实例有界内存。每次部署或服务重启都会使全部用户重新登录。用户要求在保留既有认证流程的前提下，让重启后的会话继续有效。

应用层已有 [SessionStore 端口](../../crates/application/src/ports/identity.rs)，覆盖创建、校验、单会话撤销和按用户批量撤销，因此可以替换适配器，无需重写登录用例。

## 决策

新增 `sessions` 表，使用 `PostgresSessionStore` 替换生产装配中的内存实现；测试仍可使用实现同一端口的 `InMemorySessionStore`。这在记录时使业务表总数达到 16，当前表清单以 [数据库实现参考](../database-current.md) 为准。

- **只持久化令牌摘要**。以 SHA-256 摘要作主键，明文只在签发时返回，数据库记录不能直接充当浏览器 Cookie。表中另存用户、CSRF token、签发时身份版本以及创建、活跃、绝对过期时间；CSRF token 可由同源前端读取，按明文保存。
- **保持既有期限语义**。空闲过期基于最后活跃时间，绝对期限在签发时固定；校验刷新活跃时间，但不延长绝对期限。数据库与内存适配器的比较边界一致，避免换存储时改变登录行为。
- **维护容量与撤销的事务边界**。创建的“清理过期、按需淘汰、插入”与按用户批量撤销使用同一把事务 advisory lock 串行，避免并发创建突破容量。已在锁内开始的创建完成后，撤销才能完成；排在撤销之后的创建仍需依靠身份版本绑定判定是否有效。
- **保留 `users.version` 绑定**。会话记录签发版本，验证时与账号当前版本比较，不能因存储已经共享就取消身份修订检查。
- **索引围绕实际访问设计**。主键支持令牌校验和单条撤销，用户索引支持批量撤销，绝对期限与活跃时间索引服务清理、容量淘汰。
- **注入时钟以便验证过期行为**。生产用系统时钟，测试可推进逻辑时钟，不依赖 sleep。
- **OAuth 尝试仍在进程内存**。一次性 state 在重启后作废不影响已签发的本站会话，不在本次持久化范围。

## 考虑过的方案

- `tower-sessions`：能提供 PostgreSQL 会话存储，但需要迁移到它的提取器和键值模型，再接回本项目已有的批量撤销、身份版本、CSRF 和 Cookie 语义。此次只需要存储适配器，未选择引入通用中间件。
- Redis 或独立会话服务：会增加必须维护的有状态组件；PostgreSQL 已是依赖，授权路径也读取主库。
- 将会话塞入 settings：隐藏了独立生命周期与查询模型。
- 仅使用自包含签名 Cookie：不能独立提供本项目要求的服务端即时撤销，仍需额外服务端状态。
- 只增加绝对期限、不刷新活跃时间：会改变原有空闲续期行为，让持续活跃的用户提前掉线。

## 后果与限制

服务重启不会清空本站会话，不同进程可以读取和撤销同一份会话记录。每次校验写入活跃时间，增加数据库写入负担并可能形成热点；会话数量由期限、容量淘汰和清理约束，不再依靠重启清空。

备份会包含会话行，恢复旧备份可能恢复仍持有旧 Cookie 的会话，因此恢复流程须显式撤销。

会话共享不等于完整多实例认证：OAuth 尝试和登录限流仍为进程内状态，部署多实例前必须另行处理。本决策只改变本站会话存储及其跨进程撤销能力。

## 后续变更

[ADR-0016](0016-confirmed-blog-schema.md) 保留 PostgreSQL 会话、令牌摘要、独立 CSRF 值及空闲/绝对期限，改用 `sessions.auth_version` 保存 `users.auth_version` 快照，替代 `user_version` 与业务编辑版本绑定。活跃刷新不得更新认证快照；当前账号状态、版本与期限全部通过后才刷新活跃时间。目标表同时约束活跃时间不晚于绝对期限。该设计已在新初始迁移与 PostgreSQL 会话适配器中实现；资料与角色变化保持登录，认证撤销仍跨进程生效。
