# 功能范围与实施路线

本文是功能交付状态与后续验收的唯一清单。更新日期：2026-09-28。专项文档分别说明当前契约和已采纳目标设计，ADR 保留决策过程；不在多处维护里程碑进度。

“已实现”表示仓库已有实现和对应验证，不表示已经通过生产部署验收。“待验收”与“未实现”分开记录；候选方案不因写入文档而成为本版承诺。

## 1. 已确认范围

- Rust 模块化单体：四层加 server 装配入口，共五个 crate。
- 单站点多人协作，公开 MiniJinja SSR，后台 React + TypeScript + Vite SPA；作者可直接发布自己的文章，无强制审核。
- PostgreSQL 为当前唯一数据库。新的 [19 表设计](database-design.md)已确认，包含 18 张业务表与 sessions；迁移已重写为新库基线，身份会话、媒体、内容、目录和评论已适配，保留期、新库恢复、正式媒体显式清理和已有业务写入口的事务审计已接入。
- 目标为 Post 单分类、多系列、多标签；分类可有父节点，系列采用可重复排序权重。Page 无作者，作为全站资源，具有独立回收站。
- RBAC、内置与自定义角色的方向保留；首批外部身份为通用 OIDC 与 GitHub。本地密码与持久会话按后续决策纳入。
- 扩展采用主题、Webhook 和外部服务等受限入口；多数据库、搜索、统计及其他扩展按使用场景分别立项，不提供通用可执行插件安装器。

首次预约或发布后 slug 锁定，无旧路径跳转；永久删除释放地址。会话持久化不等于完整多实例支持。已有身份、角色、媒体、内容、目录、评论和设置写入口已接入事务审计、可信来源 IP 和独立 audit.read 权限的后台只读查询；会话活跃刷新等运行事件不作为业务变更审计。没有邀请、通用任务队列或 outbox。

身份保护也有明确边界：业务内容写入尚未在统一身份锁内重新授权，OAuth 配置保存不复核最后 Owner 的实际可登录性。安装向导已实现原子首个 Owner，受控 CLI 仍保留分步初始化。这些不能由“已有 RBAC/Owner 保护”推定成立，实际规则见[身份与后台](identity-and-admin.md)。

上线验收清单：

- [ ] 确定部署规模、容量、备份频率/保留期及 RPO/RTO；记录应用构建、迁移版本与配置。
- [ ] 在拟上线环境验证登录、权限与撤权、多人编辑冲突、发布/撤回/预约、Post/Page 回收站及永久删除完整流程。
- [ ] 验证正文图片、封面、头像和 logo 的上传、授权、公开访问与回收；完成含媒体文件的空环境恢复，核验数据库引用与文件一致。
- [ ] 验证部署层能够停止全部写入；完成故障中断、秘密缺失、损坏备份、会话清空与重新开放演练，记录实际恢复点和耗时。
- [ ] 按真实内容规模测量公开读取、渲染队列、数据库和后台写入；验证过载行为及迁移/HTML 重建耗时，不用原型吞吐代替部署指标。
- [ ] 核验默认及可切换主题的移动端、键盘导航、深浅色、代码展示和阅读排版；验证实际域名下的 canonical、feed、sitemap 与静态资源。

具体恢复操作与工具缺口见[备份与恢复](operations-and-recovery.md)；勾选本清单需要对应环境的结果，代码测试通过本身不足以勾选生产项。
